# Evidence Becomes Admission Policy / 证据变成准入策略
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-08-21

**Observation cut-off / 观察截止：2026-08-21 06:43 CST**

## 0｜Executive Judgment / 核心判断

W34 前四天已经把 Agent 执行证据从 workspace 一路推进到 session、commit / PR、build artifact 与 cryptographic attestation

今天最重要的新层不是再增加一种证明格式，而是看见**证明开始直接参与运行时准入决策**

GitHub 官方文档当前明确支持在 Kubernetes 中使用 Sigstore Policy Controller 强制执行 artifact-attestation policy：部署请求在 admission 阶段被拦截，控制器验证镜像 attestation 与 trust policy，不满足要求的镜像可以被拒绝进入集群

因此昨天的：

```text
ARTIFACT
→ ATTESTATION
→ VERIFY
→ LOCAL POLICY DECISION
```

今天可以进一步具体化为：

```text
AGENT SESSION
→ REVIEWED SOURCE
→ BUILD
→ ARTIFACT
→ SIGNED ATTESTATION
→ POLICY EVALUATION
→ ADMIT / REJECT
→ RUNTIME
```

今天的核心判断是：

> **Evidence becomes operational when policy can block execution on its absence or mismatch**
>
> **只有当证据能够改变“允许 / 拒绝”结果时，它才真正进入运行治理**

但这个判断必须保留边界

GitHub 官方仍明确说明 artifact attestation 不是软件安全保证；admission policy 也只能证明“满足指定来源 / 构建要求”，不能证明 Agent 获得了正确用户授权、代码语义正确、运行结果安全或业务决策合理

## 1｜From verification to enforcement / 从验证到强制执行

昨日 H9 的重点是 source-to-artifact provenance

今天 GitHub Kubernetes admission-controller 路径给出了更强的 operational evidence：

- Sigstore Policy Controller 拦截 image admission
- `TrustRoot` 决定验证信任根
- `ClusterImagePolicy` 定义接受条件
- namespace 可以选择启用 enforcement
- 未满足 attestation / policy 要求的镜像可以被拒绝

**ANALYSIS** — provenance 从 forensic / verification object 进入 admission-control primitive

## 2｜Evidence and policy remain separate / 证据与策略仍然分离

一个 valid attestation 只能回答它声明并证明的字段

例如：

```text
artifact digest
repository
commit SHA
workflow
triggering event
build environment
```

策略层仍需要回答：

```text
which issuer / organization is trusted
which image scope is covered
which provenance predicates are required
which namespace enforces the rule
what exceptions exist
what happens after revocation / rebuild
```

因此今天新增：

> **Valid evidence ≠ acceptable policy**

## 3｜Revocation now affects consumability / 撤销开始影响可消费性

GitHub 当前还提供 attestation lifecycle management，并明确指出：如果消费者依赖 verification process，删除不再可信或不再需要的 attestation 可以使关联 artifact 无法继续通过验证流程

这让 W34 的“revocation”第一次与 delivered artifact 的实际可消费性发生直接关系

**ANALYSIS** — provenance lifecycle 不是静态存档，而开始具备 operational consequence

## 4｜The remaining Agent-specific gap / Agent 特有缺口仍然存在

当前 artifact attestation 能证明 software supply-chain provenance，但它通常并不携带：

- 哪个 Agent session 发起了源码变化
- 哪个 human initiator / sponsor 授权了 Agent
- 哪条 delegated scope 支持这次行动
- 哪个 Agent definition / policy version 实际运行
- 多 Agent / sub-agent 的贡献链

所以今天不能写成“Agent governance 已经被 SLSA / Sigstore 解决”

更准确的判断是：

> open supply-chain provenance now provides an enforcement substrate that Agent-specific accountability may need to bind into

## 5｜Workstream Findings / 分任务发现

### F1 History and theory

W34 正在重复一个成熟基础设施规律：证据只有从“可查看”进入“可执行政策”，才从记录系统变成控制系统

### F2 Models and algorithms

模型能力没有变化，但更强 Agent autonomy 会放大 admission policy 的价值，因为输出进入部署系统后已经脱离模型会话本身

### F3 Infrastructure

今天关键对象是 `TrustRoot + ClusterImagePolicy + admission controller + namespace enforcement`，说明 trust evidence 已经进入基础设施数据平面

### F4 Agentic systems

Agent runtime governance 与 software supply-chain governance 开始接近，但 Agent identity / delegation 与 build provenance 仍未正式合并

### F5 Evaluation and governance

“验证通过”必须继续拆成 provenance validity、policy acceptance、semantic correctness、security posture 与 business authorization 多个判断

### F6 Ecosystem and society

Sigstore 等开放机制可以降低 provenance 完全锁死在单一 Agent 平台里的风险，但跨 Agent authority semantics 仍然缺少开放映射

## 7｜New Durable Candidates / 新耐久候选

> **Evidence availability ≠ evidence enforcement**

> **Valid attestation ≠ acceptable deployment policy**

> **Admission success ≠ application safety**

> **Supply-chain provenance ≠ delegated Agent authority**

> **Revocation without enforcement ≠ effective revocation**
