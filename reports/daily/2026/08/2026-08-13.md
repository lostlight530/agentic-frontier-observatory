# Identity Reaches the Wire / 身份走上网络线
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-08-13

**Observation cut-off / 观察截止：2026-08-13 05:29 CST**

## 0｜Executive Judgment / 核心判断

### 中文

昨天的全球仓把 Agent 从“普通 App”进一步识别为第一类安全主体。今天，身份继续向外走了一层：**Agent 不只需要在云 IAM 里拥有身份，还开始需要在每一次 Web 请求上证明“这条流量确实来自我”**。

OpenAI 当前的 ChatGPT agent allowlisting 文档明确说明，ChatGPT agent 会对每个出站 HTTP 请求进行签名，使用 RFC 9421 HTTP Message Signatures，并携带 `Signature`、`Signature-Input` 和 `Signature-Agent`；其公钥通过 well-known 目录发现。Cloudflare 的 Web Bot Auth 文档则给出另一端的实际验证路径：Bot/Agent 发布密钥目录、签署 HTTP 请求，Cloudflare 在边缘验证后把它作为 verified bot / agent 处理。

因此，昨天的“Agent Principal / Identity”今天被拆成两个不同层级：

```text
CONTROL-PLANE IDENTITY
Who is this agent inside an organization?
→ lifecycle · sponsor · owner · workload identity · permissions

REQUEST-PLANE IDENTITY
Did this specific request really come from that agent/service?
→ public key discovery · HTTP message signature · freshness · replay controls
```

这不是说 Web Bot Auth 已经成为通用 Agent 身份协议。IETF 的自动化流量签名架构仍是 Internet-Draft；不同实现对签名字段、目录格式和反重放细节仍可能存在差异。

今天真正成立的判断是：**Agent identity 正从账户目录走向可密码学验证的网络行为**。

### English

Yesterday the observatory treated the AI agent as a first-class security principal. Today identity moves one boundary further outward: an agent increasingly needs not only an account in an IAM control plane, but a way to prove that a specific HTTP request really came from that agent or service.

OpenAI documents signed outbound ChatGPT agent requests using RFC 9421 HTTP Message Signatures and a discoverable public-key directory. Cloudflare documents Web Bot Auth as an operational verification method for bots and agents at the edge.

The emerging distinction is therefore between **control-plane identity** and **request-plane identity**. The latter cryptographically binds a service identity to concrete network traffic. This is implementation convergence around signed traffic, not proof of a universal agent-identity protocol.

## 2｜Signed traffic turns identity into evidence / 签名流量让身份变成证据

**FACT** — OpenAI documents that ChatGPT agent signs outbound HTTP requests. The receiving site can verify the signature and public key directory to confirm authentic ChatGPT agent traffic.

**FACT** — Cloudflare documents Web Bot Auth as a method for cryptographically verifying bot and agent requests, with signed messages and a published key directory.

**FACT** — RFC 9421 is the standardized HTTP Message Signatures base. The agent-specific Web Bot Auth architecture and signature-agent directory mechanisms remain IETF drafts rather than finalized RFCs.

**ANALYSIS** — Agent identity is becoming observable to systems that do not share the agent provider's internal IAM plane.

## 3｜Identity now has at least three boundaries / 身份至少出现三个边界

```text
ORGANIZATIONAL IDENTITY
Agent principal · owner · sponsor · lifecycle

PROTOCOL / WORKLOAD IDENTITY
Workload identity · token · credential · delegated user context

REQUEST IDENTITY
Signed HTTP request · key discovery · freshness · verification at origin/edge
```

The layers can compose, but they are not equivalent.

A valid signed request can prove the origin of traffic without proving that the action was authorized by a specific end user. A cloud workload identity can authorize resource access without proving how a public website should recognize the request. A human sponsor can establish accountability without being cryptographically attached to every network action.

## 4｜Workstream Findings / 分任务发现

### F1 History and theory

The Web is moving from weak bot self-identification such as User-Agent strings and IP allowlists toward cryptographic service identity. For agentic systems, this is analogous to the broader transition from naming actors to proving actors.

### F2 Models and algorithms

No model capability change is needed for this layer. The signal is architectural: action-capable models create demand for stronger external identity evidence precisely because the model can now cross organizational boundaries.

### F3 Infrastructure

Edge infrastructure becomes part of agent trust. CDNs, WAFs, origins, public-key directories, signature freshness windows and anti-replay controls become operational components of agent access.

### F4 Agentic systems

The external trust path is now clearer:

```text
Discovery
→ Principal Identity
→ Authorization
→ Credential
→ Request Signature
→ Origin / Edge Verification
→ Invocation
→ Audit
```

### F5 Evaluation and governance

Evaluation can no longer stop at “the task succeeded.” For consequential web actions, evidence should distinguish authenticated service origin, delegated user authority, requested action, policy result and final side effect.

### F6 Ecosystem and society

Cryptographically recognized agents give websites a basis for differentiated policy: allow, rate-limit, block, price, or require stronger authorization. That can reduce spoofing while also creating new gatekeeping power at the web edge.

### F7 Synthesis

W33's identity thesis is strengthened, but refined: **first-class identity is not complete until external systems can verify agent behavior at the boundary where actions occur**.

## 5｜Changed Judgments / 判断修正

### Refined H4 interpretation

Yesterday H4 focused on purpose-built agent principals in enterprise IAM.

Today the identity stack expands beyond the organization. The durable model must include request-level proof when an agent crosses into an external web origin.

### New H5 candidate

**Request-level cryptographic agent identity becomes a Web primitive.**

This remains falsifiable. It weakens if major agent ecosystems continue to rely mainly on IP lists, User-Agent strings, shared secrets or provider-specific trust relationships without broader signed-request adoption.

## 6｜Stable Judgments / 稳定判断

- Identity is not the same as a credential
- Authentication is not authorization
- A signed request does not prove end-user consent
- Control-plane identity does not automatically travel across the open Web
- Web Bot Auth drafts are not final RFCs
- Implementations can converge before specifications fully converge

## 7｜Uncertainties / 不确定项

1. Whether Web Bot Auth drafts converge into a stable interoperable standard
2. How service identity maps to an individual agent instance or run
3. How delegated end-user identity is represented without privacy leakage
4. Whether revocation propagates quickly enough to public-key directories and edge verifiers
5. How signed-agent identity composes with MCP, A2A and enterprise workload identity
6. How origins express fine-grained action policy after authenticating the agent
