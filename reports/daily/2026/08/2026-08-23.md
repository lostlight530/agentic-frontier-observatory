因此今天不新增 H12，而是结算 W34：这一周从 workspace governance 出发，逐层进入 session evidence、durable source change、build provenance、artifact attestation、runtime admission 和 evidence lifecycle

```text
AGENT DEFINITION
→ PUBLISH / IDENTITY / POLICY
→ SESSION EVIDENCE
→ DURABLE SOURCE CHANGE
→ BUILD ARTIFACT
→ SIGNED ATTESTATION
→ POLICY EVALUATION
→ ADMIT / REJECT
→ RUNTIME
→ TRUST CHANGE
→ RE-VERIFY / RE-ADMIT
```

W34 最稳定的结论不是“Agent governance 已经完全自动化”，而是：

> **治理已经从配置层进入执行链，并能通过机器可验证证据直接参与运行准入；但持续运行中的信任撤销仍未形成通用闭环**

GitHub 当前文档明确支持 artifact attestation 的生成、验证、Kubernetes admission enforcement 与 lifecycle deletion

当消费者已经建立 verification process 时，删除 attestation 可以使关联 artifact 后续不能继续通过该验证路径

但这不等于 already-running workload 会自动终止，也不等于 Agent identity、delegated authority 或跨平台 credential 会同步撤销

## 1｜From policy to execution / 从策略到执行

W34 最重要的结构变化，是 governance 不再只表现为角色、权限和人工规则

本周观察到：

- Agent definition 与 published state 被产品化区分
- connection identity、trigger、approval 和 action scope 成为执行前边界
- session telemetry 形成运行时证据
- commit / PR / review 把 Agent 行为绑定到 durable change
- artifact attestation 把 source / workflow / digest 绑定到构建产物
- admission controller 允许 policy 基于 provenance 直接决定 admit / reject
- attestation lifecycle 使已接受的 evidence 后续仍可被删除、替换和重新验证

因此治理第一次形成了明显的 execution envelope

## 2｜The boundary is layered / 执行边界是分层的

```text
EDITABLE STATE
≠ PUBLISHED STATE
≠ MERGED SOURCE STATE
≠ ATTESTED ARTIFACT STATE
≠ ADMITTED RUNTIME STATE
≠ ONGOING TRUST STATE
```

这些状态之间可以有关联，但不能自动等价

一个 Agent 定义被发布，不代表其代码已经通过 review

代码 merge，不代表 artifact provenance 已经验证

artifact 被 admit，也不代表业务授权、语义正确性和运行时安全永久成立

## 3｜Evidence can govern without proving correctness / 证据可以参与治理，但不能证明正确

本周出现了一个重要分离：

```text
EVIDENCE OF ORIGIN
→ POLICY DECISION
→ OPERATIONAL CONSEQUENCE
```

这说明 provenance 不只是“给人看的日志”

它可以成为机器决策输入

但：

> **Valid attestation ≠ safe software**

> **Admission success ≠ correct Agent behavior**

> **Artifact trust ≠ delegated Agent authority**

## 4｜Revocation remains the open edge / 撤销仍是未闭合边

GitHub 文档明确允许删除不再可信的 attestation，并指出在 consumer verification 已部署时，删除可阻止关联 artifact 继续被使用

这支持 H11：evidence lifecycle 已成为 runtime trust dependency

但当前证据仍不足以证明：

- 删除 attestation 自动停止已运行 workload
- admission policy 自动回溯所有缓存或镜像副本
- artifact evidence revocation 自动撤销 Agent credential
- delegated sub-agent authority 自动级联撤销
- MCP / A2A / cloud IAM 共享统一 revocation propagation

因此：

> **Revocation signal ≠ revocation propagation**
