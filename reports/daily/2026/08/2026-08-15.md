# Trust Crosses Domains / 信任跨越边界
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-08-15

**Observation cut-off / 观察截止：2026-08-15 06:44 CST**

## 0｜Executive Judgment / 核心判断

今天没有为了日期强造一条“8 月 15 日刚发布”的模型新闻

昨天的研究把 Agent 信任从身份与请求来源推进到可验证用户委托：系统不仅要知道“谁在行动”，还要知道“用户授权了什么”

今天继续向外扩展一层后，真正的长期问题变成：**当 Agent 穿过企业、云、SaaS、Agent 网关和第三方平台时，委托、身份、撤销、审计和 provenance 如何一起跨越信任域**

NIST NCCoE 当前仍在推进 Software and AI Agent Identity and Authorization 项目，并把 identification、authorization、auditing 和 non-repudiation 视为现实部署问题

与此同时，多项 IETF Internet-Draft 正从不同角度研究跨域 Agent 信任：有的把 trust domain、agent gateway、delegation、revocation 和 audit 组织为一个 trust substrate；有的把 capability、delegation chain、provenance 和 session receipt 放到 discovery 之上的 trust-negotiation 层；另一些则尝试以 human identity root、agent identity 和 delegation chain 表达可追责关系

因此今天的结构性判断是：

> **Agent interoperability 正从“协议能否互通”继续走向“信任能否跨域解释”**

边界必须严格保留：这些 IETF 文档仍是 work in progress，不是已经达成共识的互联网标准，也不能把多个草案的相似方向误写成统一协议

## 1｜From portable intent to cross-domain trust / 从可携带委托到跨域信任

昨天的信任链：

```text
Agent identity
→ request provenance
→ user-approved scope
→ action decision
→ outcome evidence
```

今天增加跨域维度：

```text
Human / Organizational Authority
→ Agent Identity
→ Delegated Scope
→ Local Trust Domain
→ Gateway / Cross-Domain Boundary
→ Foreign Policy Interpretation
→ Action
→ Audit / Revocation / Evidence
```

新的长期规则：

> **Interoperable transport ≠ interoperable trust**

两个 Agent 可以使用同一种传输或协作协议，但仍可能无法互相解释身份、授权范围、撤销状态、责任主体和审计证据

## 2｜NIST keeps identity and authority as a deployment problem / NIST 仍把身份与权限视为部署问题

NIST NCCoE 的 Software and AI Agent Identity and Authorization 项目当前状态为 `Reviewing Comments`

其公开项目目标是研究基于标准的方法来识别、管理并授权软件 Agent / AI Agent 的访问与行动，并形成组织可实施的实践指南

这说明身份、权限、审计与不可否认性并未被单一 Agent 协议解决，而仍是独立基础设施与治理对象

## 3｜IETF drafts expose the trust-domain layer / IETF 草案显出信任域层

### Cross-domain trust substrate

`draft-kiliram-agent-trust-auth-framework-00` 明确把企业、服务提供商、SaaS 和第三方 Agent 服务视为不同 trust domains，并指出 Agent-to-Agent transport 本身不足以提供跨域身份、授权、委托和审计

### Trust negotiation above discovery

`draft-somoza-...-agent-trust-negotiation` 把 trust negotiation 放在 discovery 之后，研究 capability manifest、delegation chain、provenance attestation 与 session receipt

### Human-anchored authority

`draft-beyer-agent-identity-architecture-00` 则把 responsible human、agent identity、delegation chain 与 provenance 放在同一概念架构中，并明确不要求新的全球统一标识或统一 credential format

这些草案彼此并不等价，也不应合并为“一个 IETF Agent 标准”

## 4｜W33 Saturday Checkpoint / W33 周六检查

### H4 — Agent identity becomes a first-class principal
**STRENGTHENED / unchanged**

跨域研究进一步证明 Agent 需要稳定身份，但身份仍必须绑定责任主体与生命周期

### H5 — Request-level cryptographic identity becomes a Web primitive
**SUPPORTED / unchanged**

今天没有新证据削弱请求级来源证明，但跨域问题说明来源证明仍只是信任链的一部分

### H6 — Delegated intent becomes portable evidence
**STRENGTHENED / REFINED**

昨天 H6 主要由 AP2/FIDO 的用户委托证据支撑

今天进一步细化为：**可携带委托只有在另一信任域能够解释其责任主体、范围、有效期、撤销与 provenance 时才真正具有跨域价值**

### New H7 — Trust domains become an explicit interoperability boundary

跨组织 Agent 互操作将越来越需要显式表达 trust domain、gateway、delegation、policy interpretation 与 audit boundary，而不是假设共享协议自动意味着共享信任

**Falsifier:** 大规模跨组织 Agent 部署长期只依赖共同 transport + 本地 IAM，即可稳定解决责任、委托、撤销与审计，而无需显式跨域信任模型

## 5｜Stable Boundaries / 稳定边界

- Internet-Draft ≠ RFC / Internet Standard
- Similar drafts ≠ standards convergence
- Discovery ≠ trust negotiation
- Identity ≠ delegation
- Delegation ≠ foreign-domain acceptance
- Session receipt ≠ task correctness
- Cross-domain trust ≠ universal trust
- Architecture model ≠ deployed interoperability

## 6｜Tomorrow's W33 closure questions / 明日 W33 收官问题
