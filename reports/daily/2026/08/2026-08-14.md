# Authority Gets a Receipt / 授权开始留下收据
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-08-14

**Observation cut-off / 观察截止：2026-08-14 05:34 CST**

## 0｜Executive Judgment / 核心判断

昨天的研究说明签名请求可以证明“这条流量确实来自某个已知 Agent 服务”

今天继续向后追一层，真正的缺口变成：**即使 Agent 身份和请求来源都真实，外部系统仍然需要知道用户到底授权了什么行动、授权范围是什么，以及验证方最终接受或拒绝了什么**

AP2 v0.2 与 FIDO Alliance 当前的 Agentic AI 工作给出了一个已经进入公开协议与标准化讨论的答案方向：把用户授权表达为可验证的 Mandate / Verifiable Intent，并让验证方返回可验证的 Receipt

因此今天的结构性判断是：

> **Agent 信任栈正在从“证明它是谁”走向“证明用户授权了什么，并为授权决定留下证据”**

边界必须严格保留：AP2 v0.2 当前面向 Agent 支付；FIDO 正在推进更广泛的 Agentic Authentication 与 Trusted Delegation 工作，这不等于已经存在一个适用于所有 Agent 行动的最终统一标准

## 1｜Evidence Boundary / 证据边界

昨天的链条回答：

```text
Agent identity
→ signed request
→ service-origin verification
```

今天增加的证据层回答：

```text
user intent
→ delegated scope
→ verifier decision
→ receipt / durable evidence
```

新的长期规则是：

> **Identity ≠ Request Proof ≠ User Intent ≠ Authority ≠ Execution ≠ Receipt**

## 2｜AP2 as concrete evidence / AP2 作为现实证据

AP2 v0.2 是面向 Agent 支付的开放协议

其公开文档明确区分 Mandate Delegation 与 Action Authorization，并使用 Checkout / Payment Mandates 与 Receipts 表达用户授权、约束和验证结果

AP2 还区分 Human Present 与 Human Not Present 流程，使自主 Agent 可以在预先授权的约束范围内执行支付，而不是默认继承用户完整权限

这说明“委托授权”已经从产品内部会话状态进入公开、机器可验证的协议设计

## 3｜FIDO moves delegation into standards work / FIDO 把委托推进标准化

Google 于 2026-04-28 发布 AP2 v0.2 并宣布将 AP2 捐赠给 FIDO Alliance

FIDO 同日宣布 Agentic Authentication Technical Working Group，并在 Agentic AI 工作中明确区分：

- Verifiable User Instructions
- Agentic Authentication
- Trusted Delegation for Commerce

FIDO 的当前工作状态说明：身份验证、用户指令与委托授权正在被视为相关但不同的标准化问题

## 4｜W33 Judgment / W33 判断

H4“Agent identity becomes a first-class principal”继续成立，但今天被进一步限定：**第一类主体仍然必须说明它代表谁行动**

H5“request-level cryptographic identity becomes a Web primitive”也继续成立，但今天的证据说明：**请求来源真实仍不等于用户授权真实**

新增：

### H6 — Delegated authority becomes portable evidence

高后果 Agent 行动将越来越需要能够表达用户意图、范围与约束的可验证授权证据，以及验证结果证据，而不是只依赖平台内部 session 或日志

**Falsifier:** 主要 Agent 生态长期仍只依靠不可携带的内部权限状态完成高后果委托行动

## 5｜Stable Boundaries / 稳定边界

- Agent identity ≠ user consent
- Signed request ≠ delegated authority
- Consent ≠ unlimited authority
- AP2 payment protocol ≠ universal Agent authorization standard
- FIDO work underway ≠ final published standard
- Authorization evidence ≠ task correctness
