### English

No same-day official release found before the cut-off overturns the previous two days. But the first three days of observation now reveal a stronger pattern: the agentic frontier is moving from the existence of protocols toward the formation of a network.

MCP’s 2026-07-28 specification moves to a stateless request/response core with header-based routing, cacheable lists, a formal extensions framework, and authorization hardening. A2A is now in a stable 1.0 era with SDK adoption following the specification. Linux Foundation’s DNS-AID adds decentralized discovery for agents and MCP servers. NIST continues to organize standards activity around interoperability, open protocols, identity, authorization, security, and evaluation.

The emerging question is no longer whether agents can exchange messages. It is whether they can be discovered, identified, authorized, evaluated, observed, and governed across organizational boundaries.

## 2｜Historical Continuity / 历史连续性

The Internet became useful not because one protocol solved every layer, but because naming, routing, identity, transport, application protocols, and operational conventions could compose

The agentic frontier is beginning to show a similar layering pressure

```text
Model intelligence
→ software harness
→ tools and data
→ protocol communication
→ discovery and reachability
→ identity and authority
→ evidence and observability
→ operational governance
```

This analogy is structural, not literal. Agent systems introduce semantic uncertainty, delegated authority, model non-determinism, and human responsibility that ordinary network endpoints do not possess

## 3｜Critical Developments / 关键变化

### 3.1 MCP is becoming infrastructure-shaped

**FACT** — The official 2026-07-28 MCP release replaces the previous session-oriented core with a stateless request/response architecture, removes the required initialize handshake and session ID, adds header-based routing, cacheable list results, formal extensions, authorization hardening, and a minimum deprecation window

**ANALYSIS** — This is not merely a feature release. Statelessness, routability, caching, and deprecation policy are infrastructure concerns. MCP is being shaped for gateways, load balancers, policy enforcement, and enterprise operations

### 3.2 A2A is moving from specification stabilization to implementation convergence

**FACT** — A2A v1.0.0 was released on 12 March 2026 and v1.0.1 on 26 May 2026. The JavaScript SDK reached stable v1.0 on 22 July 2026 with support for JSON-RPC, HTTP+JSON/REST, and gRPC transports

**ANALYSIS** — The research question now shifts from “what does A2A define?” to “how consistently do SDKs, transports, TCKs, and real systems implement the 1.x contract?”

### 3.3 Discovery is becoming a first-class Agent Internet problem

**FACT** — Linux Foundation announced DNS-AID on 27 May 2026 as a vendor-neutral approach for publishing, discovering, and verifying agents and MCP servers using DNS infrastructure

**ANALYSIS** — A protocol endpoint that cannot be securely discovered is still dependent on hardcoded integration or centralized registries. Discovery therefore sits logically before interoperability at Internet scale

### 3.4 Identity and authorization remain the unresolved trust boundary

**FACT** — NIST’s AI Agent Standards Initiative explicitly lists agent security and identity as a research pillar, while NCCoE’s Software and AI Agent Identity and Authorization project is currently reviewing comments on applying identity standards to agent use cases

**ANALYSIS** — Discovery answers “where is the agent”; identity answers “what is it”; authorization answers “what may it do on whose behalf”. These are separate questions and should remain separate in the repository taxonomy

## 4｜Workstream Findings / 分任务发现

### F1 History and theory

The agentic turn increasingly resembles a network formation problem layered on top of the model-capability problem. Historical Internet analogies are useful only when they preserve the unique uncertainty of delegated machine reasoning

### F2 Models and algorithms

No same-day model release in today’s authoritative-source pass changes the current judgment. Model quality remains necessary but insufficient to explain system reliability

### F3 Infrastructure

Stateless MCP, DNS-based discovery, transport diversity, gateways, and SDK conformance move agent research deeper into ordinary distributed-systems concerns: routing, caching, observability, backward compatibility, and failure recovery

### F4 Agentic systems

MCP, A2A, and DNS-AID are best modeled as complementary layers rather than substitutes: tool/context access, agent collaboration, and discovery/reachability

### F5 Evaluation and governance

The next evaluation frontier is conformance plus trajectory evidence. A system can speak the same protocol and still disagree semantically, propagate excessive authority, or fail recovery requirements

### F6 Ecosystem and society

Neutral foundations reduce single-vendor control, but open governance does not guarantee semantic interoperability, secure deployment, or equal bargaining power across the ecosystem

## 5｜Cross-System Analysis / 跨系统分析

The first three days now support a revised frontier stack:

```text
Model
→ Harness / Runtime
→ Tool & Data Access
→ Agent-to-Agent Coordination
→ Discovery & Reachability
→ Identity & Authorization
```

The stack should not be read as a universal architecture. It is an observation framework for separating problems that are often collapsed into the word “agent protocol”

## 6｜Changed Judgments / 修正的判断

### New durable judgment

Discovery must become its own long-term workstream concern rather than a footnote under protocols

### Strengthened judgment

Identity and authorization should be tracked together with protocol and deployment evidence, not treated as downstream enterprise administration

### Refined judgment

Protocol maturity should be measured by more than specification version: SDK convergence, conformance tooling, deployment patterns, migration policy, and observable failure behavior matter

## 7｜Stable Judgments / 稳定判断

- No material same-day official release was confirmed before the cut-off
- MCP and A2A remain complementary, not interchangeable
- Agent discovery is not solved by message interoperability alone
- Identity, delegation, authorization, and revocation remain open infrastructure problems
- Protocol compatibility does not imply semantic or behavioral compatibility
- Evidence quality remains more important than apparent freshness

## 8｜Uncertainties and Conflicts / 不确定与冲突

- DNS-based discovery and enterprise registries may coexist rather than converge
- No universal cross-vendor Agent identity model has emerged
- Conformance can test protocol behavior without proving task reliability
- Multi-agent semantic interoperability remains substantially less mature than transport interoperability
- Human responsibility for delegated authority remains institutionally fragmented
