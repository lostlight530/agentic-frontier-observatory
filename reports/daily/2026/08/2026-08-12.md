# Identity Becomes the Principal / 身份成为主体
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-08-12

**Observation cut-off / 观察截止：2026-08-12 05:23 CST**

## 0｜Executive Judgment / 核心判断

今天没有必要为了凌晨 05:23 的截止时间强行制造一条“8 月 12 日新发布”

真正改变 W33 判断的是一组已经进入现实云基础设施的跨厂商证据：Microsoft、Google Cloud 与 AWS 都已经为 AI Agent 建立专门的身份与授权抽象

这些实现并不共享同一协议，也没有证明跨云身份已经互操作，但它们在架构上出现明显收敛：**Agent 正从普通应用或借用用户身份的自动化脚本，变成拥有独立身份、生命周期、委托语义、权限边界、审计轨迹与人类责任关系的第一类安全主体**

因此昨天的链条必须继续拆细：

> **Discovery ≠ Identity ≠ Credential ≠ Authority ≠ Invocation**

知道一个 Agent 或资源存在，不等于知道是谁在行动；知道行动者身份，不等于它持有什么凭据；凭据有效，不等于拥有任意权限；拥有权限，也不等于已经执行调用

### English

No same-day headline before the 05:23 CST cut-off is needed to justify today's report. The material evidence is architectural: Microsoft, Google Cloud, and AWS now expose purpose-built identity and authorization primitives for AI agents.

They do not share one identity protocol, and this is not evidence of cross-cloud interoperability. But they converge on an important principle: **an AI agent is becoming a first-class security principal with its own identity, lifecycle, delegated or autonomous authority, audit trail, and accountable human relationship.**

## 1｜Research Scope / 今日研究范围

Today's primary-source pass covered:

- Microsoft Entra Agent ID identity, authorization, blueprints, sponsors, lifecycle and permission controls
- Google Cloud Agent Identity and workload identity semantics
- Amazon Bedrock AgentCore Identity, workload identities, inbound/outbound authorization and credential handling
- NIST/NCCoE agent identity and authorization work

## 2｜Microsoft: identity includes accountability / Microsoft：身份开始包含责任关系

**FACT** — Microsoft Entra Agent ID is generally available and defines agent identities as a distinct identity model with purpose-built governance and access controls

Agent identities are created from reusable blueprints and can have owners, sponsors and managers. Sponsors represent business accountability rather than technical administration

Authorization supports delegated and autonomous scenarios, while many high-privilege directory roles and Graph permissions are explicitly blocked for agent identities

**ANALYSIS** — Microsoft is not merely creating a token format. It is modeling the organizational life of an agent: who created its type, who owns it technically, who is accountable for its continued existence, what it may access, and what must remain forbidden

## 3｜Google: identity becomes cryptographically attested / Google：身份进入强证明层

**FACT** — Google Cloud Agent Identity defines a Google-managed identity for agentic workloads, tied to the lifecycle of the agent and based on SPIFFE

Google states that agent identities are not shared by default, cannot be impersonated, do not allow long-lived service-account keys, and use certificate-bound access tokens for Google Cloud resources

**ANALYSIS** — This shifts the trust question from “which service account does the agent borrow?” toward “which cryptographically attested agent instance is acting?”

## 4｜AWS: identity binds agents, users and credentials / AWS：身份连接 Agent、用户与凭据

**FACT** — Amazon Bedrock AgentCore Identity provides workload identities, a centralized directory, inbound authorization, outbound credential access, OAuth integration and audit-oriented access flows

AWS documentation states that workload access tokens can carry both the identity of the agent and the identity of the end user on whose behalf it is operating

**ANALYSIS** — The important unit is no longer only an agent or a human, but an accountable relationship between actor, delegator, resource and credential

## 5｜Cross-vendor convergence without protocol convergence / 架构收敛不等于协议收敛

The three systems differ materially:

- Microsoft emphasizes enterprise identity objects, blueprints, sponsorship, roles and lifecycle governance
- Google emphasizes strongly attested per-agent identity and cryptographic binding
- AWS emphasizes workload identity, inbound/outbound authorization and credential mediation across external services

The shared architectural pattern is:

```text
Agent instance
→ distinct principal
→ scoped authority
→ short-lived or mediated credentials
→ auditable action
→ lifecycle / revocation
→ accountable human or organization
```

No evidence today shows that these identity models are directly portable across providers

## 6｜Workstream Findings / 分任务发现

### F1 History and theory

The agentic era introduces a new historical category of software actor: a nonhuman system that is not merely a process, account or application but is expected to carry persistent accountability semantics

### F2 Models and algorithms

Model capability remains orthogonal to identity. A stronger model does not deserve broader authority by default

### F3 Infrastructure

Identity infrastructure now includes attestation, token issuance, credential mediation, lifecycle controls, sponsorship, risk policies and audit logs

### F4 Agentic systems

Yesterday discovery became governed. Today the next boundary becomes explicit: after selecting a resource, an agent still needs a principal identity before authority can be evaluated

### F5 Evaluation and governance

Evaluation should increasingly ask whether the correct principal acted, whether delegated authority was bounded, whether credentials were short-lived/mediated, and whether revocation and accountability were preserved

### F6 Ecosystem and society

Human responsibility does not disappear when work is delegated to nonhuman actors. Sponsor/owner models are early attempts to encode organizational accountability around autonomous software

## 7｜Changed Judgments / 判断修正

### New distinction

The previous outward stack placed Identity & Audit after invocation too coarsely

Identity must move **before authorization and invocation** because policy decisions require a principal to reason about

### Strengthened judgment

Operational trust is becoming an infrastructure discipline independent from raw model capability

## 8｜Stable Judgments / 稳定判断

- No cross-cloud identity protocol has been demonstrated by today's evidence
- Identity is not equivalent to a credential
- Authentication is not equivalent to authorization
- Delegated access must not inherit all of a human's authority implicitly
- Discovery and identity are separate layers
- Purpose-built identity documentation is evidence of architecture, not universal production adoption
