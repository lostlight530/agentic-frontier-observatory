# The Trust Stack Holds / 信任栈成立
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-08-16

**Observation cut-off / 观察截止：2026-08-16 10:37 CST**

## 0｜Executive Judgment / 核心判断

今天是 W33 第一个完整七日研究窗口的收官日

没有必要为了 8 月 16 日强行制造一个新的模型或产品头条。今天更重要的任务，是用这一周已经积累的公开权威证据判断哪些结构已经足够稳定，哪些仍然只是方向信号

W33 从 8 月 10 日的“Agentic capability 正回流核心平台”出发，随后依次观察到 governed discovery、first-class agent identity、signed request provenance、portable delegated intent 与 cross-domain trust boundary

一周结束后，最稳定的结构不是某一个协议，而是一个逐步清晰的信任栈：

```text
Native Agentic Capability
→ Governed Discovery
→ Agent Principal / Identity
→ Request Provenance
→ Delegated User Scope
→ Trust-Domain Boundary
→ Policy Interpretation
→ Action
→ Audit / Revocation / Evaluation
```

因此今天的核心判断是：

> **Agent capability 正逐渐原生化，而可追责行动需要一个独立于模型能力之外的信任栈**

这不等于统一 Agent Trust 标准已经形成

NIST 仍把 Agent identification、authorization、auditing 与 non-repudiation 作为现实部署问题；当前多份 IETF Agent 身份、授权、委托与跨域信任材料仍是 Internet-Draft / work in progress，而不是 IETF 共识标准

## 1｜W33 durable structure / 本周稳定结构

### Capability can move inward

OpenAI Atlas 的退场与 browser-based agentic capability 向 ChatGPT / Codex 回流，以及 Google 把 computer use 作为 Gemini 3.5 Flash 内置工具，支持一个本周稳定判断：通用行动能力可以被核心 AI 产品吸收

### Trust stays explicit

但 discovery、identity、authorization、request proof、delegation、revocation 和 audit 并不会因为行动能力原生化而消失

相反，它们变成跨产品、跨组织、跨协议部署时必须显式解决的基础设施

## 2｜Identity is now more than an account / 身份已经不只是账户

Microsoft Entra Agent ID、Google Cloud Agent Identity 与 Amazon Bedrock AgentCore Identity 提供了跨供应商的架构证据：生产 Agent 正被建模为独立工作负载 / 安全主体，并拥有生命周期、责任人、凭据和权限语义

本周因此保留：

> **Identity ≠ Credential ≠ Authority**

身份回答“谁在行动”

凭据回答“如何证明身份”

权限回答“允许做什么”

三者不能合并成一个字段

## 3｜Request proof and delegated intent are separate / 请求来源与用户委托必须分开

OpenAI 当前对 ChatGPT agent 出站 HTTP 请求使用 RFC 9421 HTTP Message Signatures；Cloudflare 也把 Web Bot Auth 用于 bot / agent 请求验证

这些实现支持请求级来源证明，但不能证明具体用户授权了某项行动

AP2 v0.2 与 FIDO 当前 Agentic AI 工作则提供另一类证据：用户指令、delegation、mandate 与 receipt 正在被单独结构化

因此 W33 保留另一条稳定规则：

> **Authenticated service origin ≠ delegated user authority**

## 4｜Cross-domain trust remains unresolved / 跨域信任仍未完成

`draft-kiliram-agent-trust-auth-framework-00` 明确指出 transport 本身不足以提供跨 trust domain 的身份、授权、委托与审计

`draft-klrc-aiagent-auth-02` 则倾向复用 WIMSE 与 OAuth 等既有标准来建立 Agent authentication / authorization，而不是直接发明一整套新协议

`draft-somoza-...-agent-trust-negotiation` 继续把 capability、delegation 与 provenance 放到 discovery 之上的 trust-negotiation 层

这些材料方向相近，但并不代表标准已经收敛

因此：

> **Interoperable transport ≠ interoperable trust**

仍然只是本仓的耐久观察规则，而不是互联网已经完成的事实

## 5｜W33 Final Hypothesis Settlement / W33 最终假设结算

| Hypothesis | Final status | Judgment |
|---|---|---|
| H1 — Agentic capability becomes native | **DURABLE** | 多个核心平台已把通用行动能力吸收到主产品 / 模型表面 |
| H2 — durable differentiation moves upward/outward | **STRENGTHENED BUT OPEN** | Harness、identity、authorization、evaluation 更重要，但仍需更长生产证据 |
| H3 — protocol success requires operational evidence | **DURABLE DOCTRINE** | migration、conformance、identity、failure handling 必须和 spec publication 分开 |
| H4 — Agent identity becomes a first-class principal | **DURABLE** | 多云身份体系已经给出跨供应商实现证据 |
| H5 — request-level cryptographic identity becomes a Web primitive | **STRENGTHENED BUT OPEN** | 已有真实实现，但 Agent-specific Web 标准仍在演进 |
| H6 — delegated intent becomes portable evidence | **STRENGTHENED BUT OPEN** | AP2/FIDO/授权草案提供强信号，尚未形成通用跨域实践 |
| H7 — trust domains become an explicit interoperability boundary | **OPEN / STRONG DESIGN SIGNAL** | NIST 与多个 I-D 指向该层，但缺稳定跨组织生产证据 |

没有 H1–H7 被本周证据明确推翻

但 H2、H5、H6、H7 都不能被写成“已经解决”

## 6｜Durable W33 Doctrine / W33 耐久规则

```text
Capability ≠ Deployability
Discovery ≠ Authorization ≠ Invocation
Identity ≠ Credential ≠ Authority
Authenticated Origin ≠ Delegated User Authority
Transport Interoperability ≠ Trust Interoperability
Protocol Publication ≠ Operational Maturity
Evidence of Scope ≠ Task Correctness
```

## 7｜What carries into W34 / 带入下周的问题

1. A2A / MCP 是否继续产生 migration、TCK、conformance 和生产故障处理证据
2. Agent identity 能否从单一云 IAM 映射到 signed request 与跨域 delegation
3. Web Bot Auth / request identity 哪些部分进入更稳定标准化阶段
4. delegation / mandate / receipt 是否从支付场景扩展到更一般的高后果 Agent 行动
5. 跨 trust domain 的 revocation、policy translation 与 audit 是否出现真实部署证据
6. 全球仓继续维持模型、算力、科研、具身、开源与社会面宽扫描，避免退化成 IAM / protocol observatory
