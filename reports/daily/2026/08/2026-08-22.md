# Admission Becomes Revocable / 准入开始具有撤销生命周期
## Global AI Daily Research Report / 全球人工智能每日研究报告

**Observation cut-off / 观察截止：2026-08-22 10:47 CST**

## Executive Judgment / 核心判断

W34 昨天已经把 Agent-produced artifact 的来源证明推进到 machine-enforced admission：验证不再只是“给人看”，而可以直接影响 artifact 是否被允许进入 runtime

今天继续追问更难的一层：**如果一个已经被接受的 provenance 证据后来不再可信，信任能否被撤回，并传播到后续消费与运行决策**

GitHub Artifact Attestations 的 lifecycle 文档明确指出，attestation 可以被查找和删除；当消费者配置了 verification process 后，删除 attestation 可以阻止关联 artifact 继续被使用。GitHub 也提供按 attestation ID 或 subject digest 删除的 REST API

这使 W34 的链条从一次性 admission 继续变成 evidence lifecycle：

```text
AGENT SESSION
→ REVIEWED SOURCE
→ BUILD
→ ARTIFACT
→ ATTESTATION
→ ADMISSION POLICY
→ ADMIT / REJECT
→ TRUST CHANGE / INCIDENT
→ ATTESTATION DELETE / SUPERSEDE
→ RE-VERIFY / RE-ADMIT
```

但今天最关键的边界是：

> **Attestation revocation ≠ runtime termination**

GitHub 文档说明的是未来 verification / consumption 可以失败，并没有证明已经运行的 workload 会自动退出、缓存 artifact 会自动删除，或者 Agent authority 会被同步撤销

因此今天的核心判断是：**evidence lifecycle 已经成为 deployment trust 的真实组成部分，但 end-to-end revocation propagation 仍是开放问题**

## Evidence / 证据

### 1. Admission already consumes provenance

GitHub 的 Kubernetes admission 文档显示，Sigstore Policy Controller、TrustRoot 和 ClusterImagePolicy 可以在 image admission 前验证 provenance policy，并拒绝不符合条件的 artifact

### 2. Attestations have a lifecycle

GitHub 允许搜索和删除 attestations，并明确建议删除与不再可信 artifact 关联的 attestation

### 3. Deletion can affect future consumption

当消费者有 verification process 时，删除 attestation 后对应 artifact 将无法再通过该验证路径

### 4. Runtime propagation is not established

没有证据证明 attestation 删除自动终止已经运行的 workloads，或者自动撤回已经下发给 Agent / service 的业务授权
