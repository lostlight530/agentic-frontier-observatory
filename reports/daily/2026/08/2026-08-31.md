# Reference Is Not Authority / 引用不是权限
## Global AI Daily Research Report / 全球人工智能每日研究报告

## 0｜Executive Judgment / 核心判断

August closes with a real correction to the recovery model.

The current normative A2A definition already contains a generic cross-task reference primitive:

```text
Message.referenceTaskIds
= task IDs referenced for additional context
```

This narrows one W35 open question. The missing object is **not** “any way to reference a prior Task.” Generic reference already exists.

The remaining gap is typed recovery lineage:

```text
referenceTaskIds
≠ predecessor
≠ supersedes
≠ repairs
≠ compensates
≠ incident relation
```

A second, independently useful piece of official evidence was published on **2026-08-07** but is first observed by this repository on **2026-08-31**: A2A Java SDK 1.2.0.Final hardened authorization for referenced Tasks. The release states that referenced-task lookup previously could populate related Tasks without a read-authorization check, allowing unauthorized task-existence probing; 1.2.0.Final enforces read authorization on referenced-task lookups.

That produces a durable month-end rule:

> **Task reference ≠ Task authority.**

```text
semantic / contextual relation
≠ permission to read the referenced execution
```

The publication date and repository observation date remain separate. This is not rewritten as a new 31 August SDK release.

No evidence reviewed today establishes a universal typed recovery-lineage schema across A2A, MCP and vendor-local runtimes.

## 3｜Critical Developments / 关键变化

### 3.1 Normative A2A reference primitive

The current A2A protocol definition describes `reference_task_ids` / `referenceTaskIds` as a list of Task IDs a Message references for additional context.

That is a real protocol primitive for semantic relationship.

It does not type the relationship as:

- predecessor
- supersedes
- repairs
- compensates
- rollback-of
- incident-member

### 3.2 Referenced-task authorization was hardened in the Java SDK

A2A Java SDK 1.2.0.Final was published 7 August 2026.

The official release notes say the SDK now enforces read authorization on all referenced-task lookups. The stated pre-fix risk was that an unauthorized caller could probe whether a Task existed by referencing it.

This is implementation evidence for an important boundary:

```text
reference target exists
≠ caller may read it
```

### 3.3 NIST identity / authorization remains an active project

NIST NCCoE currently shows `Software and AI Agent Identity and Authorization` as **Reviewing Comments**.

This remains governance / project-status evidence, not a finalized universal identity standard.

### 3.4 MCP task semantics remain extension-scoped

The 2026-07-28 MCP specification remains the canonical current release; Tasks are tracked through the current Tasks extension, whose page remains Draft.

No month-end evidence justifies describing the Tasks extension as finalized core semantics.

## 9｜Watchlist / 下一轮观察点

W36 opens with five falsifiable hypotheses.

### H36-1 — Generic references evolve into typed recovery lineage
A protocol extension or interoperable profile will distinguish predecessor / supersedes / repairs / compensates relations.

**Falsifier:** mature cross-system recovery remains reliable using only untyped references plus local conventions.

### H36-2 — Referenced/predecessor Task access remains independently authorized
Relationship traversal will be governed by read/operation authorization rather than inherited from reference presence.

**Falsifier:** secure mature systems safely expose referenced Task state to callers without an independent authorization decision.

### H36-3 — Incident correlation becomes portable across execution namespaces
One trace/incident relation will span A2A Task IDs, MCP task IDs and vendor-local session/remediation records.

**Falsifier:** reliable cross-system incident reconstruction needs no shared correlation mechanism.

### H36-4 — Exception / break-glass becomes a portable lifecycle object
Exception authority will carry owner, reason, scope, expiry and audit evidence.

**Falsifier:** mature systems safely scale permanent or unstructured bypasses.

### H36-5 — Non-code outputs gain remediation semantics
Documents, messages, tickets, CRM state, datasets and infrastructure mutations will gain explicit withdraw / supersede / compensate primitives.

**Falsifier:** consequential non-code outputs remain safely governed with no durable remediation state.
