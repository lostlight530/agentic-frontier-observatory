## 0｜Executive Judgment / 核心判断

今天的权威来源扫描没有发现必须用“8 月 19 日刚发布”来重写 W34 的单一事件

真正推进昨天“Session Evidence”判断的，是持久变更对象与会话证据之间已经出现直接绑定

GitHub 已经为 Copilot coding agent 的 commit 写入 `Agent-Logs-Url` trailer，让每个 Agent commit 可以永久回链到完整 session logs；同一类 Agent 工作又通过 branch、pull request、review、checks 与 audit history 进入既有软件变更控制

因此今天的核心判断是：

> **运行证据只有绑定到持久、可审查的变更对象，才开始形成真正可追责的 provenance chain**

```text
TASK / ISSUE
→ AGENT SESSION
→ SESSION LOGS
→ AGENT-AUTHORED COMMIT
→ PULL REQUEST
→ REVIEW / CHECKS
→ MERGE DECISION
→ DURABLE HISTORY
```

这不等于“Agent provenance 已经标准化”

`Agent-Logs-Url` 是 GitHub 产品实现；PR / review / checks 是成熟的软件治理结构；二者的组合可以证明可追溯性增强，但不能自动证明代码正确、安全或授权链完整

## 1｜Session evidence becomes durable provenance / 会话证据开始变成持久来源链

**FACT** — GitHub states that Copilot coding agent commits are authored by Copilot, with the human task initiator marked as co-author

**FACT** — Those commits can contain an `Agent-Logs-Url` trailer that links permanently back to the full Agent session logs

**ANALYSIS** — Yesterday's runtime trace can now survive beyond an ephemeral session view and attach to a durable code-history object

This creates a stronger chain of custody:

```text
who initiated
→ which Agent session
→ what the Agent did
→ which commit resulted
→ which PR carried the change
```

## 2｜Reviewable provenance is stronger than telemetry alone / 可审查来源链强于单纯遥测

GitHub's Copilot app policy documentation states that Agent sessions run in isolated workspaces and land changes through pull requests, preserving the same reviews, checks and audit history as other contributions

OpenAI's Codex materials similarly position pull-request review as a place where the system can compare stated intent with the actual diff and run code/tests to validate behavior

**ANALYSIS** — Session evidence becomes more valuable when it is bound to a change-control object that humans and automated checks can inspect

## 3｜The execution envelope now needs a change-control tail / 执行边界需要变更控制尾部

W34 now extends to:

```text
PRE-EXECUTION
publish / identity / policy / trigger

IN-EXECUTION
prompt / response / tool call / task state

POST-EXECUTION
session trace
→ commit provenance
→ pull request
→ review / checks
→ merge / reject
→ audit / policy feedback
```

This is an observatory synthesis, not a universal Agent governance standard

## 5｜Workstream Findings / 分任务发现

### F1 History and theory

Software engineering already has mature change-control institutions. Agent governance is beginning to reuse them rather than inventing governance entirely from scratch

### F2 Models and algorithms

No same-day model event before cut-off changes the model trajectory. The limiting question today is provenance and integration, not raw reasoning capability

### F3 Infrastructure

Durable provenance requires stable identifiers and links across session, commit, PR, review and audit stores

### F4 Agentic systems

A production coding Agent should be modeled as both an execution process and a producer of reviewable artifacts

### F5 Evaluation and governance

`session trace → commit → PR → review/checks` is stronger evidence than session logs alone, but checks remain partial evidence and human review remains fallible

### F6 Ecosystem and society

Reusing existing pull-request governance can lower adoption friction because organizations do not need a completely separate approval institution for Agent-generated changes

### F7 Synthesis

W34 is evolving from governed execution into **governed, reviewable, provenance-linked execution**

## 6｜Durable Rule Candidates / 耐久规则候选

> **Session trace ≠ durable provenance**

> **Commit provenance ≠ review approval**

> **Review / checks ≠ semantic correctness**

> **Merge decision ≠ proof of safe authorization**
