## 0｜Executive Judgment / 核心判断

### 中文

今天在观察截止前没有必要强行制造一个“8 月 11 日新发布”事件。真正改变 W33 判断的证据来自一个此前尚未纳入仓库的基础设施层：**Agentic Resource Discovery（ARD）与 GitHub Agent Finder 正在把智能体能力发现从手工接线和目录搜索，推进为受 registry、组织策略和用户选择约束的治理表面**

Microsoft 于 2026 年 6 月 17 日发布 ARD，定位为面向 Agent、MCP Server、API、Workflow 等资源的开放发现规范。ARD 的目标不是建立唯一全球目录，而是允许多个 discovery service 在本地控制、上游来源和开放生态之间形成联邦式发现。其规范仓库当前明确标记为 **v0.9 Draft**

同日 GitHub 发布 Agent Finder，作为 ARD 的实际产品实现：它可查询 GitHub 公共目录或组织私有 registry，并受企业 managed settings 约束；更关键的是，它**不会自动安装或静默连接发现到的资源**

因此今天最重要的结构不是“发现更智能”，而是：

> **Discovery ≠ Authorization ≠ Invocation**

一个 Agent 可以知道某项能力存在，并不代表它获准使用，也不代表连接已经建立。发现层本身开始承载组织边界、来源选择、排序与可用性治理

### English

No same-day release before the observation cut-off needs to be manufactured into a trend. The material evidence is an infrastructure layer not yet represented in the observatory: Agentic Resource Discovery (ARD) and GitHub Agent Finder are turning capability discovery from manual wiring into a governed surface constrained by registries, organizational policy, and explicit user choice.

ARD was introduced on 17 June 2026 as an open discovery specification for agents, MCP servers, APIs, workflows, and other callable resources. Its canonical repository currently labels the specification **v0.9 (Draft)**. GitHub Agent Finder provides operational evidence: it can query a public or private registry, obey managed settings, and deliberately does not auto-install discovered resources.

The durable distinction is simple: **discovery is not authorization, and authorization is not invocation.**

## 2｜ARD creates a pre-invocation layer / ARD 建立调用前发现层

**FACT** — ARD describes a common layer for publishing, indexing, and discovering agentic resources

**FACT** — Discovery metadata includes what a resource does, how it is invoked, who operates it, what authority it requires, and whether it fits a user, organization, or policy environment

**FACT** — The canonical spec is currently v0.9 Draft and includes conformance tooling

**ANALYSIS** — ARD is not a replacement for MCP or A2A. It sits earlier in the path: decide what capability may be relevant, then invoke through an appropriate protocol or API

```text
Capability Publication
→ Discovery
→ Selection
→ Authorization
→ Invocation
→ Execution Evidence
```

## 3｜Federation makes discovery a governance problem / 联邦发现本身就是治理问题

Microsoft explicitly rejects the idea of one universal catalog. Different discovery services may index different resources, serve different populations, and rank differently. This is closer to a federated control model than to one web search engine

That matters because whoever controls the discovery service also controls the candidate set an agent can see

**ANALYSIS** — Discovery becomes a policy boundary before any permission check occurs. An enterprise can reduce risk not only by denying invocation, but by controlling which resources are discoverable in the first place

## 4｜GitHub Agent Finder provides operational evidence / GitHub 给出产品级证据

GitHub Agent Finder implements ARD and exposes three important controls:

1. registry selection — public catalog or private organizational registry
2. managed settings — enterprise policy limits what agents may discover and use
3. no auto installation — discovery does not silently wire the resource into the agent

This is stronger evidence than a draft specification alone because it shows how a discovery layer can coexist with human and enterprise control

## 5｜Workstream Findings / 分任务发现

### F1 History and theory

The web separated naming, search, authorization, and execution into different systems. Agent infrastructure is beginning to repeat that decomposition for capabilities rather than documents

### F2 Models and algorithms

No model-level event before the cut-off changes yesterday's judgment. The relevant capability today is external to model intelligence: deciding which resource should even enter the model's actionable environment

### F3 Infrastructure

Registries, indexes, ranking, federation, metadata schemas, and conformance tests are becoming infrastructure primitives. Discovery quality will depend on freshness, provenance, policy scope, and ranking behavior, not only semantic matching

### F4 Agentic systems

ARD, MCP, and A2A occupy different positions:

```text
ARD — discover candidate capabilities
MCP — connect applications/models to tools and context
A2A — discover and collaborate with independent agents
```

The exact overlaps remain an open mapping problem

### F5 Evaluation and governance

GitHub's no-auto-install boundary is important: finding a capability does not authorize it. Enterprise AI Controls add a separate governance layer around agent activity, policies, audit logs, and MCP allowlists

### F6 Ecosystem and society

Federated discovery can preserve ecosystem plurality, but ranking and registry control become new power centers. Open protocols do not eliminate governance; they relocate it into registries, policy scopes, metadata, and trust signals

## 6｜Cross-System Analysis / 跨系统分析

Yesterday's outward interoperability stack can now be refined:

```text
Resource Publication
→ Federated Discovery / Registry
→ Ranking & Policy Scope
→ User / Organization Selection
→ Authorization
→ Invocation via MCP / A2A / API
→ Identity & Audit
→ Conformance / Evaluation / Governance
```

The missing bridge between an open ecosystem and a production enterprise is increasingly visible: **governed discovery**

## 8｜Stable Judgments / 稳定判断

- ARD v0.9 is a draft, not a stable standard
- Discovery does not equal authorization
- Authorization does not equal invocation
- A registry result does not prove resource quality or safety
- A2A Agent Cards, DNS-AID, ARD, MCP registries, and enterprise catalogs may overlap but are not interchangeable
- Broad AI coverage remains required even when agent infrastructure produces the strongest signal

## 9｜Uncertainties and Watchlist / 不确定与观察点

2. Whether authority requirements become machine-verifiable discovery metadata

4. Whether private and public discovery can merge without leaking organizational resources
5. Whether ARD conformance proves only schema compatibility or meaningful cross-client behavior
6. How discovered MCP/A2A resources inherit enterprise authorization and revocation
7. Whether discovery itself becomes a security policy enforcement point
