# Persistence is not recovery / 状态持久化不等于副作用恢复
## Global AI Daily Research Report — 2026-10-09 (Asia/Shanghai)

## 0｜Executive Judgment
**MATERIAL LATE RECONCILIATION / NO NEW SAME-DAY PROTOCOL TRANSITION.** A2A Project's official JavaScript SDK `v1.3.0` GitHub release was **published 2026-09-29T10:40:16Z**, while this observatory first verifies it on **2026-10-09 Asia/Shanghai**. Its release notes explicitly add **database-backed task and push-notification stores**. This is a concrete SDK/runtime-state implementation increment, **not** a new A2A protocol version, verified cross-SDK conformance, automatically authorized task recovery, external-effect rollback, or universal durable execution.

The current official SDK documentation describes `DatabaseTaskStore` (task snapshots, status, message history, artifacts) and `DatabasePushNotificationStore` (webhook configs/tokens/authentication credentials), with PostgreSQL/MySQL/SQLite/Cloudflare D1 support. Database migrations are operator-managed; in-memory stores lose state on restart. Current docs warn that push-notification credentials are stored as plaintext in `config_data` and completed-task configs are not automatically removed. These are **documented implementation/security/retention properties**, not a reproduced live-deployment audit.

## 5｜Evaluation, Trust, Security and Governance
The current SDK guide explicitly says stored push-notification `config_data` includes webhook authentication credentials in **plaintext**, and completed-task configurations persist until client deletion. This is a bounded documented retention/security property, not a confirmed exploit or production incident. `IDENTITY != CREDENTIAL != AUTHORITY`; storage of task state does not grant successor-task authority. `SECURITY != EXECUTION != DURABLE EFFECTS != RECOVERY`. ## 8｜Counterexample and Falsifiability
A persisted `Task` can coexist with an externally committed but unrecorded effect, a stale or changed `ownerResolver`, or plaintext webhook credentials retained after task completion. This is a strong counterexample to **`PERSISTENT_TASK_STORE == DURABLE_EFFECT_RECOVERY`**. Retest on crash/restart plus external-effect reconciliation, authorization freshness, config retention controls, and independent conformance artifacts.
