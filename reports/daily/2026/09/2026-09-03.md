## 0｜Executive Judgment / 核心判断

本轮完成 F1–F7 全面复查，发现一项需要精确化的 MCP Tasks 状态边界

当前权威表面同时成立：

- `SEP-2663: Tasks Extension` — Status **Final**
- `Tasks` extension specification — **Draft**
- extension identifier — `io.modelcontextprotocol/tasks`

这不是矛盾，而是两个不同对象拥有不同状态：

```text
proposal / SEP lifecycle: Final
specification maturity: Draft
```

因此此前“`MCP Tasks extension — Draft`”的 shorthand 需要收窄为：**Tasks specification remains Draft; SEP-2663 itself is Final**

这不是把 Tasks 升格为 finalized protocol maturity，更不是 operational maturity

其他关键判断保持：

- A2A `referenceTaskIds` 仍只是 additional-context task references
- typed recovery lineage 仍 OPEN
- NIST NCCoE Software and AI Agent Identity and Authorization 仍 Reviewing Comments
- `F.748.93` 仍 Approved on 2026-08-29 under AAP

## 3｜Agent Runtime / Protocol Findings

### 3.1 A2A

当前 normative definition 仍将 `referenceTaskIds` 定义为：message references to task IDs for additional context

因此：

- `referenceTaskIds != typed recovery lineage`
- `Task reference != Task authority`
- context linkage does not grant successor authority

本轮未发现 normative predecessor / supersedes / repairs / compensates recovery relation进入 A2A core

### 3.2 MCP Tasks

`SEP-2663` 页面标记：

- Status: Final
- Type: Extensions Track
- Extension Identifier: `io.modelcontextprotocol/tasks`

与此同时 Tasks specification 页面仍标记 `Draft`

该规范定义 durable task state machine、`tasks/get`、`tasks/update`、`tasks/cancel` 等机制，但 specification Draft 不能因 SEP Final 而被提升为 finalized interoperability maturity

### 3.3 NIST NCCoE

当前项目页仍明确显示 `Status: Reviewing Comments`

comment period closed ≠ project finalized

## 4｜Recovery Model / 恢复模型

四层模型继续保持：

```text
SECURITY
EXECUTION
DURABLE EFFECTS
RECOVERY
```

MCP Tasks 的 durable task handle 解决的是特定 task-lifecycle state representation，不自动回答：

- committed external effects
