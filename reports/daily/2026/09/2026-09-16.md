# Authorization Surfaces Deepen, Recovery Authority Still Does Not / 授权表面更明确，恢复权限仍未闭环
## Global AI Daily Research Report / 全球人工智能每日研究报告
### 2026-09-16

## 0｜Executive Judgment / 核心判断
本轮完成 F1–F7 全量复核。A2A 当前 specification 明确提供 `TASK_STATE_AUTH_REQUIRED` in-task authorization flow，并明确：协议本身不定义该 authorization decision / credential 的 scope、representation、validity 或 revocation semantics；该状态转换本身不得被视为任何具体操作的授权；同一 Task 上后续消息也不得自动继承此前授权，除非 implementation、credential issuer 或 extension 明确定义。

这是对 authority boundary 的重要当前规范证据，但不是新的 successor authority、continuous authorization、revocation lifecycle 或 recovery completion contract。A2A `referenceTaskIds` 仍只是 related-task context reference；未验证 typed predecessor/supersedes/repairs/compensates lineage。MCP `SEP-2663` 仍为 Final / Extensions Track；NIST NCCoE Software and AI Agent Identity and Authorization 仍为 `Reviewing Comments`；`F.748.93` publication state 无新变化。

W38 H38-1~H38-5 保持 `OPEN`。今天的 A2A evidence 细化 H38-4 的边界，但不因同一 source lineage 被机械计为 independent strengthening。

## 1｜Research Scope / 今日研究范围
检查 F1–F7，并保持 capability > discovery > identity > authority > execution > runtime trust > revocation > recovery > governance；使用 SECURITY / EXECUTION / DURABLE EFFECTS / RECOVERY 四层模型。

## 2｜Historical Continuity / 历史连续性
此前判断 `Authenticated Origin != Delegated User Authority`、`Admission != Continuous Authorization`、`Context Continuity != Authority Continuity` 保持。今天的 A2A normative text 使“不自动继承 authority”边界更明确，但 observation_date=`2026-09-16` 不等于该规范条款的 publication/event date。

## 3｜Critical Developments / 关键变化
- A2A in-task authorization: `TASK_STATE_AUTH_REQUIRED` 可把授权满足责任委托给 client；authorization scope/representation/validity/revocation semantics 仍由 implementation、issuer 或 extension 定义。
- A2A follow-up/context: `referenceTaskIds` 明确为 additional context；未发现 `supersedes`、rollback 或 compensation typed recovery relations。
- MCP: `SEP-2663` remains Final / Extensions Track; task extension incubation != core operational maturity.
- NIST NCCoE Agent Identity and Authorization remains `Reviewing Comments`.
- ITU `F.748.93`: no material change from 2026-09-15 observation.

## 5｜Cross-System Analysis / 跨系统分析
Current task protocols increasingly expose execution and authorization-request state, but portable contracts for successor authority, committed effects, retained state, rollback/compensation and recovery completion remain unverified in the checked sources. This is source-bounded analysis, not a universal absence claim.

## 6｜Changed Judgments / 修正的判断
No hypothesis state transition. The authority model is refined: A2A now provides directly verified normative evidence that an authorization-required task state is not itself authorization and does not automatically authorize subsequent messages.

## 7｜Stable Judgments / 稳定判断
`Capability != Deployability`; `Discovery != Authorization != Invocation`; `Identity != Credential != Authority`; `Authenticated Origin != Delegated User Authority`; `Protocol Publication != Operational Maturity`; `Admission != Continuous Authorization`; `Runtime Stop != Rollback`; `Termination != Remediation`; `Context Continuity != Authority Continuity`; `referenceTaskIds != typed recovery lineage`; `Task reference != Task authority`.
