## 6｜Progress Check — 2026-08-12

### New evidence

Three major cloud identity stacks now provide concrete evidence that AI agents are becoming first-class security principals rather than generic applications or borrowed user accounts.

- **Microsoft Entra Agent ID** introduces agent identities, reusable blueprints, owners/sponsors/managers, delegated and autonomous permissions, lifecycle governance, Conditional Access, audit, and explicit blocking of many high-privilege roles and permissions
- **Google Cloud Agent Identity** provides a strongly attested cryptographic identity per agent, tied to the agent lifecycle, based on SPIFFE; identities are not shared by default, cannot be impersonated, and Google Cloud access tokens are certificate-bound
- **Amazon Bedrock AgentCore Identity** provides workload identities, a centralized identity directory, inbound/outbound authorization, token and credential management, and user-agent binding for delegated access

This is **architectural convergence**, not evidence of a shared cross-cloud identity protocol.

### New H4 — Agent identity becomes a first-class principal

Production AI agents will increasingly require purpose-built identities with explicit lifecycle, accountability, delegated/autonomous authority, and audit semantics rather than being modeled only as human users or generic app service principals.

**Falsifier:** major production ecosystems continue to scale agents primarily through undifferentiated user/app identities without purpose-built lifecycle or policy constructs.

### Weekly model refinement

```text
Discovery
→ Selection
→ Agent Principal
→ Sponsor / Owner / Blueprint
→ Authentication
→ Delegated or Autonomous Authorization
→ Credential / Token
→ Invocation
→ Audit / Revocation / Lifecycle
```

New durable rule:

> **Identity ≠ Credential ≠ Authority**

A principal can be identified without holding a credential directly; a credential can authenticate without granting arbitrary authority; delegated authority can be narrower than the human sponsor's full access.

### New W33 questions

- Can Microsoft, Google, AWS, NIST, MCP, and A2A identity semantics be mapped without flattening their different trust models?
- Can an agent carry accountable identity across cloud and protocol boundaries without becoming a shared long-lived credential?
- How should human sponsorship, business accountability, and technical ownership be represented in open protocols?
- Can revocation and lifecycle termination propagate across discovered resources and delegated subagents?
