### H1 — Agentic capability becomes native
Standalone action wrappers will increasingly be absorbed into core AI products and models.

### H3 — Protocol success requires operational evidence
Protocols will increasingly be judged by migration, conformance, discovery, identity, observability, and production failure handling rather than publication alone.

### H4 — Agent identity becomes a first-class principal

Production agents will increasingly require purpose-built identities with lifecycle, sponsorship/ownership, delegated or autonomous authority, and audit semantics.

**Falsifier:** major ecosystems continue to scale agents primarily through undifferentiated user/app identities without agent-specific lifecycle or policy constructs.

Rule refined:

> **Identity ≠ Credential ≠ Authority**

## 6｜Progress Check — 2026-08-13

### New evidence

OpenAI currently documents that ChatGPT agent signs every outbound HTTP request using RFC 9421 HTTP Message Signatures and exposes a public-key directory so websites and edge services can verify authentic agent traffic.

Cloudflare documents Web Bot Auth as an operational verification method for bots and agents, including key directories, signed requests, `Signature-Agent`, freshness windows and edge verification.

The underlying HTTP Message Signatures mechanism is standardized in RFC 9421, while the bot/agent-specific Web Bot Auth architecture and signature-directory details remain IETF Internet-Drafts.

### Hypothesis status

| Hypothesis | Status | 13 Aug evidence |
|---|---|---|
| H1 — capability becomes native | **SUPPORTED / unchanged** | No evidence today weakens platform consolidation |
| H2 — moat moves upward/outward | **STRENGTHENED AGAIN** | Web-edge identity verification becomes independent infrastructure |
| H3 — operational evidence matters | **STRENGTHENED AGAIN** | OpenAI and Cloudflare expose concrete signed-request behavior, not only design prose |
| H4 — identity becomes a first-class principal | **STRENGTHENED / REFINED** | Identity now extends beyond IAM accounts into externally verifiable request traffic |

### New H5 — Request-level cryptographic agent identity becomes a Web primitive

Action-capable agents will increasingly need cryptographic request identity that external origins and intermediaries can verify independently of provider-internal IAM.

**Falsifier:** large-scale agent traffic continues to depend mainly on User-Agent strings, IP allowlists, shared secrets or bilateral provider trust without broader signed-request adoption.

### Weekly model refinement

```text
CONTROL PLANE
principal → sponsor / owner → permissions → lifecycle

REQUEST PLANE
key directory → signed request → freshness / anti-replay
→ edge / origin verification → policy decision
```

New rule:

> **Authenticated service origin ≠ delegated user authority**

A website may prove that traffic is genuinely from a known agent service while still lacking proof that a specific human authorized a particular action.

### New W33 questions

- Can cloud agent identity map cleanly onto request-level Web identity?
- Can delegated user context cross the boundary without privacy leakage?
- How quickly can revocation/key rotation propagate to public verifiers?
- Will signed request identity compose with MCP, A2A, payments and fine-grained authorization?
- Which parts of Web Bot Auth become stable standards versus provider-specific practice?
