# Live Trust / 持续信任
## Global AI Weekly Research — 2026-W35 Progress
### Watch window: 2026-08-24 → 2026-08-30
### Updated: 2026-08-26

> **From Executable Governance to Runtime Trust Propagation**  
> **从可执行治理，走向运行时信任传播**

## 0｜Current Weekly Judgment / 当前周度判断

W34 proved that machine-verifiable evidence can participate in runtime admission

W35 asks:

> **Can a trust change alter the state of something that is already active?**

The week is now separating three distinct control layers

```text
ADMISSION-TIME
artifact provenance
→ policy evaluation
→ admit / reject

LIVE ACCESS
identity / risk / policy change
→ relying resource
→ allow / deny / claims challenge

AGENT RUNTIME
session / compute
→ continue / steer / stop / cancel
→ persistent side effects remain separately governed
```

25 August provided a concrete resource-side revocation path

26 August adds explicit runtime-stop implementations from GitHub and Microsoft Foundry

This advances the weekly model without closing the final propagation gap

> **Resource denial ≠ runtime stop**

and

> **Runtime stop ≠ rollback**

## 1｜W35 Hypothesis Progress / 假设进展

### H1 — Runtime trust requires continuous re-evaluation

**STRONGLY STRENGTHENED**

Continuous trust is now supported by both live resource enforcement and explicit runtime lifecycle controls

### H2 — Revocation requires an explicit enforcement point

**STRONGLY STRENGTHENED / REFINED**

W35 now has two separate implementation-level enforcement surfaces:

- a relying resource can reject stale access and require fresh evaluation
- an Agent platform can explicitly stop a running session / compute environment

**Open edge:** public evidence still does not show a portable policy bridge automatically connecting the first to the second

### H3 — Artifact trust and workload identity remain distinct but correlated

**SUPPORTED / unchanged**

Runtime-stop state adds another lifecycle dimension rather than collapsing provenance and identity

### H4 — Short-lived identity does not replace policy revocation

**STRENGTHENED / unchanged**

Credential expiry/rotation does not define runtime-stop semantics, cleanup or rollback

### H5 — Exception paths become lifecycle objects

**OPEN**

No new evidence closes break-glass / temporary-exception ownership, expiry and audit

### H6 — Non-code Agent outputs need equivalent lifecycle boundaries

**OPEN / stronger pressure**

Stopping a runtime cannot automatically retract already-published documents, tickets, CRM changes, infrastructure mutations or datasets

### H7 — End-to-end correlation becomes incident infrastructure

**STRENGTHENED**

A complete incident now requires correlation across:

```text
trust event
→ resource denial
→ stop/cancel control
→ stopped session / compute
→ preserved artifacts and side effects
→ cleanup / resume decision
```

### H8 — Relying-resource participation becomes part of revocation infrastructure

**STRONG IMPLEMENTATION SIGNAL / unchanged**

Microsoft workload-identity CAE remains strong but scoped evidence that resource-side participation can make a trust change operational

### H9 — Explicit Agent-runtime termination becomes a first-class control primitive

**NEW / MULTI-PLATFORM IMPLEMENTATION SIGNAL**

GitHub and Microsoft Foundry both expose explicit stop controls for Agent sessions/runtimes

GitHub stopping a coding-agent session ends the associated GitHub Actions run while preserving already-pushed commits

Microsoft Foundry stopping a hosted Agent session terminates running compute while preserving persistent filesystem state for later resume

**Falsifier:** mature autonomous Agent platforms consistently govern incidents through resource denial alone and do not require an explicit session/runtime cancellation or termination primitive

## 2｜Monday Evidence / 24 August

### GitHub — admission and evidence lifecycle

Artifact attestations can participate in Kubernetes admission policy and can later be deleted

**Boundary:** attestation deletion does not prove automatic termination of already-running workloads

### NIST — continuous session evaluation

NIST Zero Trust models continued evaluation of active sessions and permits continue / limit / revoke decisions through PDP / PEP enforcement

**Boundary:** general access-control architecture, not an Agent-specific standard

### SPIFFE — live workload identity

Short-lived workload credentials and automatic rotation make live identity state dynamic

**Boundary:** workload identity ≠ delegated Agent authority

## 3｜Tuesday Evidence / 25 August

### Microsoft Entra — CAE for workload identities

For supported workload identities and resources:

```text
trust / risk change
→ relying resource
→ token rejected
→ 401 claims challenge
→ new token
→ conditions evaluated again
```

**Boundary:** current documented support remains constrained and does not establish universal Agent runtime revocation

## 4｜Wednesday Evidence / 26 August

### GitHub — Stop session

GitHub Agent-session management exposes `Stop session`

Stopping the session ends the associated GitHub Actions run and preserves commits already pushed

This proves a concrete Agent-task runtime transition while also proving that stop is not rollback

### Microsoft Foundry — hosted session stop

Foundry exposes REST / SDK session-stop operations

Stopping a hosted session:

- terminates running compute
- preserves persistent filesystem state
- permits later resume
- scopes stop authority through the documented isolation mechanism

This provides a second implementation where STOPPED and DELETED are separate lifecycle states

## 5｜Research Priorities / 本周优先问题

1. Can identity-risk / CAE / policy events automatically invoke an Agent-runtime stop API?
2. Can one stop decision propagate across parent Agent, subagents, tools and remote runtimes?
3. What happens to in-flight tool calls when stop is requested?
4. Are external credentials revoked when compute stops?
5. Can resume require fresh trust evaluation rather than simply restarting preserved state?
6. How are durable side effects rolled back, superseded or remediated after stop?
7. Can one incident correlation ID span issuer → resource → Agent runtime → durable outcome?
8. Do open protocols develop portable cancel / terminate / resume semantics?

## 6｜Evidence Discipline / 证据纪律

```text
admission ≠ continuous authorization
revocation event ≠ propagated revocation
issuer decision ≠ resource enforcement
resource denial ≠ runtime stop
runtime stop ≠ rollback
stop ≠ delete
stop ≠ credential revocation
stop control ≠ automatic trust propagation
preserved state ≠ safe state
session termination ≠ revocation of every external side effect
```
