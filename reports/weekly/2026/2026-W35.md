The weekly conclusion is deliberately scoped:

> **Agent runtime governance increasingly requires separate state for trust, execution, durable effects, remediation and successor authority. Public evidence does not yet expose one portable cross-system incident/recovery object binding all of them.**

## 2｜Evidence Added This Week / 本周新增证据

### 24 August — live trust after admission

NIST runtime access-control patterns, SPIFFE workload identity and attestation/admission evidence separated admission-time trust from ongoing runtime trust.

### 25 August — relying-resource enforcement

Microsoft workload CAE provided a concrete supported pattern where trust-relevant changes can reach a participating resource, cause token rejection / claims challenge and force re-evaluation.

Scope remained narrow: supported resources / identity types only.

### 26 August — runtime becomes explicitly stoppable

GitHub Agent sessions and Microsoft Foundry hosted sessions supplied explicit stop controls with documented state-retention semantics.

### 27 August — termination leaves residue

OpenAI operation cancellation, GitHub session stop / revert semantics and Foundry retained state separated:

```text
cancel operation
≠ stop session
≠ delete retained state
≠ revert / compensate durable effect
```

### 28 August — recovery gets a new task boundary

A2A terminal-task semantics and MCP durable Tasks supplied strong precedent for treating recovery as a new auditable execution identity rather than invisible resurrection of a terminal task.

### 29 August — recovery must reauthorize

A2A request security and `TASK_STATE_AUTH_REQUIRED` semantics strengthened the rule that context continuity does not imply authority continuity.

### 30 August — stable recheck

The current A2A specification still keeps `contextId`, Task identity and authorization scope separate; `AUTH_REQUIRED` is not itself authorization for an operation and does not automatically authorize later messages.

MCP cancellation remains cooperative. No Sunday protocol maturity transition required a new hypothesis.

## 4｜Durable and Changed Judgments / 稳定与变化判断

W35 establishes these durable boundaries:

```text
admission ≠ continuous authorization
revocation signal ≠ revocation propagation
issuer decision ≠ resource enforcement
resource denial ≠ runtime stop
cancel operation ≠ stop session
stop session ≠ delete retained state
runtime stop ≠ rollback durable effects
terminal task ≠ incident closure
context continuity ≠ task restart
context continuity ≠ authority continuity
new task ≠ inherited authorization
AUTH_REQUIRED ≠ authorization proof
authentication ≠ authorization
authorization ≠ user intent
```

The weekly shift is from “revocation as one event” to “incident state distributed across multiple enforcement and recovery objects.”

## 5｜Corrections and Counterevidence / 更正与反证

No material source conflict refuted the W35 chain.

The evidence repeatedly narrowed over-broad formulations:

- CAE resource denial does not prove Agent-process termination
- stop controls do not prove automatic trust-signal propagation
- terminal Task semantics do not define compensation
- new Task identity does not itself establish current authority
- `AUTH_REQUIRED` does not itself authorize anything
- request authorization does not prove every downstream side effect is separately authorized

These are constraints, not footnotes; they define the durable claim boundary.

## 6｜Models, Infrastructure, Agents, and Governance / 模型、基础设施、智能体与治理

W35 closes with four distinct state planes:

```text
SECURITY
principal → credential → authentication → authorization / policy

EXECUTION
operation → Task → session / runtime → terminal state

DURABLE EFFECTS
commits / files / messages / artifacts / external mutations

RECOVERY
incident → inventory → remediation → successor task → validation
```

Model capability remains necessary but insufficient to describe any of these governance states.

A2A, MCP, cloud IAM and product-local runtime controls remain complementary rather than one interoperable stack.
