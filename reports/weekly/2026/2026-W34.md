# Governed Execution / 受控执行
## Global AI Weekly Research — 2026-W34
### Watch window: 2026-08-17 → 2026-08-23

> **From Trust Stack to Governed Execution**  
> **从信任栈，走向受控执行**

## 0｜Opening Baseline / 开周基线

W33 已经结算：Agent capability 可以原生化，但 accountable agency 仍需要显式 trust stack

W34 不重新证明 identity / delegation 是否重要，而是追问：**这些 trust primitives 如何进入真实 workspace、enterprise control plane、shared connections、schedules、API triggers、publishing 与 runtime approval，并形成可验证的 execution envelope**

当前可观察的产品结构包括：

- OpenAI Workspace Agents 的 draft / publish、RBAC、shared agents、schedule、API trigger、connection identity、write approvals 与 action constraints
- GitHub Agent Control Plane 的 agent session visibility、audit、enterprise policy 与 MCP governance
- Microsoft Entra Agent ID 的 owner / sponsor、access package、expiry、Conditional Access 与 lifecycle governance

这些产品不构成统一协议，但足以建立 W34 的研究窗口

## 1｜W34 Working Hypotheses / 工作假设

### H1 — Governance becomes a product primitive

Agent governance will increasingly be exposed directly inside mainstream Agent products as publishing, sharing, connection, trigger, approval, observability, and audit controls rather than remaining an external security afterthought

**Falsifier:** major Agent products continue to rely primarily on external IAM / manual policy without first-class in-product governance primitives

### H2 — Published state becomes an execution boundary

The distinction between editable draft and published live configuration will become operationally important for shared and scheduled Agents

**Falsifier:** Agent platforms converge on immediate live mutation without meaningful version / publish / rollback boundaries while remaining governable at scale

### H3 — Connection identity becomes a first-class authority dimension

End-user identity, agent-owned identity, service identity, and delegated identity will increasingly require explicit separate representation

**Falsifier:** shared Agent systems scale while treating all downstream connections as a single undifferentiated credential context

### H4 — Policy closure requires more than write approval

Runtime governance will split into at least access, action constraint, write approval, data-return control, runtime observation, and audit layers

**Falsifier:** one unified policy primitive reliably covers these functions without meaningful blind spots or ambiguity

### H5 — Human accountability persists above autonomous execution

Organizations will maintain explicit owner / sponsor / accountable-human relationships for production Agents even as invocation and execution automate

**Falsifier:** production deployments broadly abandon human or organizational accountability anchors without creating equivalent lifecycle responsibility mechanisms

### H6 — Vendor-local governance will pressure open interoperability

As workspace and enterprise controls become richer, MCP / A2A / Web identity and cross-domain trust will need ways to preserve authority semantics across platform boundaries

**Falsifier:** cross-platform Agent workflows scale through bilateral integrations while governance semantics remain safely and durably vendor-local

### H7 — Session evidence becomes a governance primitive

Structured session-level evidence will increasingly become a first-class governance object rather than relying only on coarse audit events

**Falsifier:** production Agent governance scales broadly without session-level prompt / response / tool / state evidence or an equivalent structured execution record

## 2｜Priority Questions / 本周优先问题

1. draft / publish / rollback 是否成为 Agent 配置治理的共同模式
2. who-can-run 与 who-authenticates-downstream 如何分开表达
3. schedule / API / Slack / IDE trigger 是否共享一致权限边界
4. write approval 与 parameter constraint 是否能覆盖高风险实际操作
5. connector output / data-return governance 如何补上 action-constraint 盲区
6. owner / sponsor / operator / end user 之间责任如何映射
7. audit 是否可以重建 definition version、trigger、identity、delegation、action 与 outcome
8. session telemetry 是否能重建 prompt / response / tool call / task state
9. MCP / A2A 是否出现携带这些治理与 trace 语义的正式映射

## 3｜Evidence Ladder / 证据门槛

```text
PRODUCT DOCUMENTATION
< OPERATIONAL IMPLEMENTATION
< STRUCTURED SESSION EVIDENCE
< CROSS-PRODUCT REPEATABILITY
< FORMAL MAPPING / CONFORMANCE
< CROSS-DOMAIN PRODUCTION EVIDENCE
```

单个平台拥有一个设置，不足以证明通用模式

多个平台出现类似结构可以强化架构判断，但仍不等于标准收敛

## 5｜2026-08-18 Progress Check / 第一次进展检查

GitHub Copilot Agent session streaming provides direct enterprise visibility into prompts, responses and tool calls across multiple Copilot surfaces, with streaming and REST access; Agent Control Plane already records Agent actor identity, represented user and task lifecycle events

This strengthens the W34 execution-envelope model by adding a runtime evidence layer

```text
PRE-EXECUTION
publish / identity / policy / trigger

IN-EXECUTION
prompt / response / tool call / state

POST-EXECUTION
audit / SIEM / review / revocation / policy update
```

### Hypothesis status

- **H1 — STRENGTHENED:** governance is visible both before execution and during/after sessions
- **H2 — SUPPORTED / unchanged:** no evidence weakens publish as a live-state boundary
- **H3 — SUPPORTED / unchanged:** runtime evidence increases the need to correlate acting Agent and represented user
- **H4 — STRENGTHENED:** preventive controls alone do not close governance without runtime observation
- **H5 — STRENGTHENED:** enterprise SIEM / audit workflows preserve an organizational accountability layer
- **H6 — OPEN:** session evidence remains vendor-local by today's evidence
- **H7 — NEW:** session evidence becomes a governance primitive

### New boundary

> **Session visibility ≠ execution correctness**

Telemetry can establish what was observed, not automatically whether authority, safety, correctness or recovery were adequate

## 6｜Current Boundaries / 当前边界

- workspace control ≠ open standard
- draft/publish ≠ safety guarantee
- shared connection ≠ delegated user authority
- write approval ≠ data-return governance
- audit log ≠ task correctness
- session streaming ≠ correctness proof
- prompt / response visibility ≠ delegated-authority proof
- vendor telemetry schema ≠ cross-platform observability standard
- sponsor ≠ runtime approver
- rich vendor governance ≠ cross-platform governance portability
