# Governed Execution / 受控执行
## Global AI Weekly Research — 2026-W34
### Watch window: 2026-08-17 → 2026-08-23

> **From Trust Stack to Governed Execution**  
> **从信任栈，走向受控执行**

## 0｜Opening Baseline / 开周基线

W33 已经结算：Agent capability 可以原生化，但 accountable agency 仍需要显式 trust stack

W34 追问这些 trust primitives 如何进入真实 workspace、runtime observation、durable source change、delivered artifact 与 deployment admission，并形成可验证、可阻断的 execution envelope

## 1｜W34 Working Hypotheses / 工作假设

### H1 — Governance becomes a product primitive
Agent governance will increasingly appear directly inside Agent products and delivery systems as publishing, sharing, connection, trigger, approval, observability, audit, review, provenance and admission controls

### H2 — Published state becomes an execution boundary
Editable Agent definition, published Agent state, merged source state, attested artifact state and admitted runtime state will become operationally distinct governance boundaries

### H3 — Connection identity becomes a first-class authority dimension
End-user identity, agent-owned identity, service identity and delegated identity will require explicit separate representation

### H4 — Policy closure requires more than write approval
Runtime governance will split into access, action constraint, write approval, data-return control, observation, review, provenance verification, admission policy and exception handling

### H5 — Human accountability persists above autonomous execution
Organizations will preserve owner / sponsor / initiator / reviewer / approver relationships for production Agents

### H6 — Vendor-local governance will pressure open interoperability
MCP / A2A / Web identity / Sigstore-style evidence will increasingly need mappings that preserve authority and provenance across platform boundaries

### H7 — Session evidence becomes a governance primitive
Structured session evidence will increasingly become a first-class governance object

### H8 — Durable change artifacts become provenance anchors
Commits, pull requests and equivalent reviewable artifacts will increasingly anchor Agent execution evidence to change control

### H9 — Build artifact attestation becomes a deployment provenance boundary
Agent-generated software entering delivery pipelines will increasingly require machine-verifiable source-to-artifact provenance

### H10 — Machine-verifiable evidence becomes a runtime admission primitive
Deployment systems will increasingly use attestation and policy evidence to automatically admit or reject Agent-produced artifacts before runtime

**Falsifier:** provenance verification remains only advisory while production deployment broadly proceeds without any machine-enforced equivalent admission boundary

## 2｜Evidence Ladder / 证据门槛

```text
PRODUCT DOCUMENTATION
< OPERATIONAL IMPLEMENTATION
< STRUCTURED SESSION EVIDENCE
< DURABLE SOURCE-ARTIFACT LINKAGE
< CRYPTOGRAPHIC BUILD ATTESTATION
< MACHINE POLICY EVALUATION
< ADMIT / REJECT ENFORCEMENT
< CROSS-PRODUCT REPEATABILITY
< FORMAL MAPPING / CONFORMANCE
< CROSS-DOMAIN PRODUCTION EVIDENCE
```

密码学证据与 admission enforcement 都不能替代 semantic correctness、business authorization 或 runtime safety

## 5｜Current Durable Candidates / 当前耐久候选

```text
Session trace ≠ durable provenance
Session provenance ≠ source provenance ≠ build provenance
Artifact attestation ≠ security proof
Evidence availability ≠ evidence enforcement
Valid attestation ≠ acceptable deployment policy
Admission success ≠ application safety
Supply-chain provenance ≠ delegated Agent authority
Revocation without enforcement ≠ effective revocation
```

## 6｜Open Questions / 未决问题

1. Agent session / identity / sponsor metadata 是否进入 custom attestation predicates
2. provenance policy 是否能与 delegated-authority policy 组合而不混淆
3. attestation deletion / revocation / rebuild 是否能传播到 runtime
4. exception policy 是否形成新的 bypass surface
5. MCP / A2A 产生的 non-code outputs 是否获得等价 admission primitive
6. one correlation ID 能否从 Agent definition → session → PR → artifact → runtime
7. policy decision 本身是否产生可审计、可回放 evidence

## 7｜Current Boundaries / 当前边界

- workspace control ≠ open standard
- session streaming ≠ correctness proof
- commit-to-session link ≠ universal provenance standard
- review / checks ≠ semantic correctness
- artifact attestation ≠ Agent-specific provenance standard
- verified provenance ≠ delegated authority
- valid attestation ≠ deployment approval
- admission success ≠ software safety
- Sigstore policy enforcement ≠ complete Agent governance
