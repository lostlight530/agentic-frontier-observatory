# Governed Execution / 受控执行
## Global AI Weekly Research — 2026-W34
### Watch window: 2026-08-17 → 2026-08-23

> **From Trust Stack to Governed Execution**  
> **从信任栈，走向受控执行**

## 0｜Opening Baseline / 开周基线

W33 已经结算：Agent capability 可以原生化，但 accountable agency 仍需要显式 trust stack

W34 不重新证明 identity / delegation 是否重要，而是追问：**这些 trust primitives 如何进入真实 workspace、enterprise control plane、shared connections、schedules、API triggers、publishing、runtime observation 与 durable change control，并形成可验证的 execution envelope**

## 1｜W34 Working Hypotheses / 工作假设

### H1 — Governance becomes a product primitive
Agent governance will increasingly be exposed directly inside mainstream Agent products as publishing, sharing, connection, trigger, approval, observability, audit and review controls rather than remaining an external security afterthought

**Falsifier:** major Agent products continue to rely primarily on external IAM / manual policy without first-class in-product governance primitives

### H2 — Published state becomes an execution boundary
The distinction between editable draft and published live configuration will become operationally important for shared and scheduled Agents

**Falsifier:** Agent platforms converge on immediate live mutation without meaningful version / publish / rollback boundaries while remaining governable at scale

### H3 — Connection identity becomes a first-class authority dimension
End-user identity, agent-owned identity, service identity, and delegated identity will increasingly require explicit separate representation

**Falsifier:** shared Agent systems scale while treating all downstream connections as a single undifferentiated credential context

### H4 — Policy closure requires more than write approval
Runtime governance will split into access, action constraint, write approval, data-return control, runtime observation, review and audit layers

**Falsifier:** one unified policy primitive reliably covers these functions without meaningful blind spots or ambiguity

### H5 — Human accountability persists above autonomous execution
Organizations will maintain explicit owner / sponsor / accountable-human relationships for production Agents even as invocation and execution automate

**Falsifier:** production deployments broadly abandon human or organizational accountability anchors without equivalent responsibility mechanisms

### H6 — Vendor-local governance will pressure open interoperability
As workspace and enterprise controls become richer, MCP / A2A / Web identity and cross-domain trust will need ways to preserve authority semantics across platform boundaries

**Falsifier:** cross-platform Agent workflows scale safely while governance semantics remain durably vendor-local

### H7 — Session evidence becomes a governance primitive
Structured session-level evidence will increasingly become a first-class governance object rather than relying only on coarse audit events

**Falsifier:** production Agent governance scales broadly without session-level prompt / response / tool / state evidence or an equivalent structured execution record

### H8 — Durable change artifacts become provenance anchors
Commits, pull requests and equivalent reviewable artifacts will increasingly anchor Agent execution evidence to human review and organizational change control

**Falsifier:** production Agent change workflows scale without durable links among initiator, session, generated artifact, review and integration decision

## 2｜Priority Questions / 本周优先问题

1. draft / publish / rollback 是否成为 Agent 配置治理的共同模式
2. who-can-run 与 who-authenticates-downstream 如何分开表达
3. schedule / API / Slack / IDE trigger 是否共享一致权限边界
4. write approval、action constraints、data-return governance 如何组合
5. owner / sponsor / operator / end user 之间责任如何映射
6. session telemetry 是否能重建 prompt / response / tool call / task state
7. commit / PR 是否能稳定绑定回 session、Agent definition 与 human initiator
8. review / checks 是否能产生 Agent-specific evidence rather than generic pass/fail
9. MCP / A2A 是否出现携带 governance / trace / provenance 语义的正式映射
10. non-code Agents 是否拥有同等级持久 provenance artifact

## 3｜Evidence Ladder / 证据门槛

```text
PRODUCT DOCUMENTATION
< OPERATIONAL IMPLEMENTATION
< STRUCTURED SESSION EVIDENCE
< DURABLE ARTIFACT LINKAGE
< REVIEW / CHECK EVIDENCE
< CROSS-PRODUCT REPEATABILITY
< FORMAL MAPPING / CONFORMANCE
< CROSS-DOMAIN PRODUCTION EVIDENCE
```

单个平台拥有一个设置，不足以证明通用模式

多个产品出现类似结构可以强化架构判断，但仍不等于标准收敛

## 6｜2026-08-19 Progress Check / 第二次进展检查

GitHub now provides a durable binding from Copilot coding-agent commits back to full session logs through an `Agent-Logs-Url` commit trailer; the human who initiated the task is preserved as co-author

GitHub's Copilot app governance also lands changes through pull requests with the same reviews, checks and audit history used by ordinary contributions

This extends the W34 envelope:

```text
PRE-EXECUTION
publish / identity / policy / trigger

IN-EXECUTION
session / prompt / tool / state

POST-EXECUTION
session trace
→ agent-authored commit
→ pull request
→ review / checks
→ merge / reject
→ durable history / policy feedback
```

### Hypothesis status — 19 Aug

- **H1 — STRENGTHENED AGAIN:** governance now spans configuration, runtime evidence and change control
- **H2 — STRENGTHENED / REFINED:** published Agent state and PR/merge state are distinct execution-to-integration boundaries
- **H3 — SUPPORTED / unchanged**
- **H4 — STRENGTHENED:** review/checks add post-execution controls unavailable to write approval alone
- **H5 — STRENGTHENED AGAIN:** initiator, co-author, reviewer and merger preserve accountability anchors
- **H6 — OPEN:** provenance binding remains vendor-local
- **H7 — STRENGTHENED / REFINED:** session evidence gains value when bound to durable artifacts
- **H8 — NEW:** durable change artifacts become provenance anchors

### New durable candidates

> **Session trace ≠ durable provenance**  
> **Commit provenance ≠ review approval**  
> **Review / checks ≠ semantic correctness**  
> **Merge decision ≠ proof of safe authorization**
