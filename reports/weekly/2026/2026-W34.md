# Governed Execution / 受控执行
## Global AI Weekly Research — 2026-W34
### Watch window: 2026-08-17 → 2026-08-23

> **From Trust Stack to Governed Execution**  
> **从信任栈，走向受控执行**

## 0｜Opening Baseline / 开周基线

W33 已经结算：Agent capability 可以原生化，但 accountable agency 仍需要显式 trust stack

W34 不重新证明 identity / delegation 是否重要，而是追问：**这些 trust primitives 如何进入真实 workspace、enterprise control plane、shared connections、publishing、runtime observation、durable source change 与 delivered artifact，并形成可验证的 execution envelope**

## 1｜W34 Working Hypotheses / 工作假设

### H1 — Governance becomes a product primitive
Agent governance will increasingly be exposed directly inside mainstream Agent products and delivery systems as publishing, sharing, connection, trigger, approval, observability, audit, review and provenance controls

**Falsifier:** major Agent products continue to rely primarily on external IAM / manual policy without first-class governance primitives

### H2 — Published state becomes an execution boundary
Editable Agent definition, published Agent state, merged source state and delivered artifact state will become operationally distinct governance boundaries

**Falsifier:** Agent systems scale while immediate mutation, source integration and artifact delivery remain one undifferentiated live state

### H3 — Connection identity becomes a first-class authority dimension
End-user identity, agent-owned identity, service identity, and delegated identity will increasingly require explicit separate representation

**Falsifier:** shared Agent systems scale while treating all downstream connections as one credential context

### H4 — Policy closure requires more than write approval
Runtime governance will split into access, action constraint, write approval, data-return control, runtime observation, review, provenance verification and deployment policy

**Falsifier:** one unified policy primitive reliably covers these functions without meaningful blind spots

### H5 — Human accountability persists above autonomous execution
Organizations will maintain explicit owner / sponsor / initiator / reviewer / approver relationships for production Agents even as invocation and execution automate

**Falsifier:** production deployments broadly abandon human or organizational accountability anchors without equivalent responsibility mechanisms

### H6 — Vendor-local governance will pressure open interoperability
As workspace and enterprise controls become richer, MCP / A2A / Web identity and cross-domain trust will need ways to preserve authority and provenance semantics across platform boundaries

**Falsifier:** cross-platform Agent workflows scale safely while governance semantics remain durably vendor-local

### H7 — Session evidence becomes a governance primitive
Structured session-level evidence will increasingly become a first-class governance object rather than relying only on coarse audit events

**Falsifier:** production Agent governance scales broadly without session-level prompt / response / tool / state evidence or an equivalent record

### H8 — Durable change artifacts become provenance anchors
Commits, pull requests and equivalent reviewable artifacts will increasingly anchor Agent execution evidence to human review and organizational change control

**Falsifier:** production Agent change workflows scale without durable links among initiator, session, generated artifact, review and integration decision

### H9 — Build artifact attestation becomes a deployment provenance boundary
Agent-generated software entering delivery pipelines will increasingly require machine-verifiable linkage from source state and build workflow to the artifact that is actually consumed or deployed

**Falsifier:** production Agent-generated software scales broadly while consumers and deployers do not require any equivalent source-to-artifact provenance mechanism

## 2｜Priority Questions / 本周优先问题

1. draft / publish / rollback 是否成为 Agent 配置治理的共同模式
2. who-can-run 与 who-authenticates-downstream 如何分开表达
3. session evidence 能否稳定关联 Agent definition、identity 与 policy version
4. commit / PR 是否能稳定绑定回 session 与 human initiator
5. review / checks 是否能产生 Agent-specific evidence
6. build artifact 是否能绑定 reviewed source SHA 与 workflow identity
7. Agent session / delegation metadata 能否进入 build attestation
8. verification 如何与 deployment policy 分离
9. MCP / A2A 是否出现携带 governance / trace / provenance 语义的正式映射
10. non-code Agents 是否拥有同等级持久 provenance artifact

## 3｜Evidence Ladder / 证据门槛

```text
PRODUCT DOCUMENTATION
< OPERATIONAL IMPLEMENTATION
< STRUCTURED SESSION EVIDENCE
< DURABLE SOURCE-ARTIFACT LINKAGE
< CRYPTOGRAPHIC BUILD ATTESTATION
< REVIEW / POLICY EVIDENCE
< CROSS-PRODUCT REPEATABILITY
< FORMAL MAPPING / CONFORMANCE
< CROSS-DOMAIN PRODUCTION EVIDENCE
```

单个平台拥有一个设置不足以证明通用模式

密码学来源证明也不能替代语义正确性、授权和部署策略

## 7｜2026-08-20 Progress Check / 第三次进展检查

GitHub Artifact Attestations extend provenance beyond reviewed source changes into the software artifact itself

Attestations create cryptographically signed claims that can bind an artifact to repository, organization, environment, commit SHA, workflow and triggering event; GitHub uses Sigstore and documents verification by consumers

```text
AGENT SESSION
→ SOURCE CHANGE
→ PR / REVIEW / MERGE
→ BUILD WORKFLOW
→ ARTIFACT DIGEST
→ SIGNED ATTESTATION
→ VERIFY
→ LOCAL POLICY / DEPLOYMENT DECISION
```

### Hypothesis status — 20 Aug

- **H1 — STRENGTHENED AGAIN:** governance now reaches delivery provenance
- **H2 — STRENGTHENED / REFINED AGAIN:** published Agent state, merged source state and attested artifact state are distinct boundaries
- **H3 — SUPPORTED / unchanged**
- **H4 — STRENGTHENED AGAIN:** verification still requires separate deployment policy
- **H5 — SUPPORTED / unchanged:** review and deployment decisions preserve organizational accountability
- **H6 — STRENGTHENED / PARTIAL SUPPORT:** Sigstore and SLSA-compatible provenance provide a more open layer, but Agent authority semantics remain unportable
- **H7 — SUPPORTED / unchanged**
- **H8 — STRENGTHENED / REFINED:** durable source artifacts become anchors for downstream build provenance
- **H9 — NEW:** build artifact attestation becomes a deployment provenance boundary

### New durable candidates

> **Session provenance ≠ source provenance ≠ build provenance**  
> **Artifact attestation ≠ security proof**  
> **Signed attestation ≠ policy acceptance**  
> **Verification ≠ authorization to deploy**

## 8｜Current Boundaries / 当前边界

- workspace control ≠ open standard
- session streaming ≠ correctness proof
- commit-to-session link ≠ universal provenance standard
- review / checks ≠ semantic correctness
- artifact attestation ≠ Agent-specific provenance standard
- Sigstore usage ≠ complete cross-platform Agent governance
- SLSA build level ≠ software safety certification
- verified build provenance ≠ valid delegated authority
- verified artifact ≠ approved deployment
